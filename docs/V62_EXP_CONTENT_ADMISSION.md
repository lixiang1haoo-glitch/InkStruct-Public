# v6.2 exp：内容准入与来源重试

应用 0.1.32 新增独立方法 `v62`，显示为 v6.2 exp（推荐）。`v61` 和 v4 adaptive 保留；Python 库版本、字体格式和文档协议不随应用补丁号递增。

## 模型与边界

沿用 v6.1 的结构修正、完整部件/嵌套视图、同字整组排除、来源映射、放置、边界、真实笔段交叉接触、组装及逐点来源校验。新增层只判断选材是否兼容，不修改源顶点、压力、笔内时间，不将笔迹拉直或弯折。

规则版本 `v62-content-admission-v1`，生成版本 `desktop-semantic-v62-20261020.1`。来源完整、语义覆盖、协议有效、人工评价分别理解；不是通用汉字语义识别器。

### 竖弯钩

方向签名不再是该类候选的唯一检索键。参考曲线先检查向下、向右及终端上钩角色，再在归一化弧长窗口 0.10–0.475 上区分主要竖干和斜干。竖干横移/参考高度至多 0.22，斜干从 0.28 起，中间保留不确定带；主要下行量至少 0.45。实际笔迹容许更宽的自然倾斜：横移至多 0.50，下行量至少 0.25。分类与平移、正等比尺度无关。

参考角色需要明确末端上钩，避免将只有上提收笔的竖提误认为竖弯钩；实际笔迹不要求逐段复制参考角度。对目标已明确的竖弯钩，参考类型或实际主要竖干证据不足则拒绝该候选。此规则的阈值是在本批开发样本上核对的有界规则，没有独立留出泛化结论。

合格候选跨原方向桶检索，仍逐一执行原映射置信度、同字排除、等比拟合、长度、端点、最终边界及交叉接触门槛。串行与批量使用同一准入层，批量描述符与串行计算一致。无合格来源仍为显式参考缺口。

### 止部关键笔

区分普通止部的竖、横与走底的撇、捺，检查四笔止部后两笔。既覆盖完整止部，也覆盖更大父部件及仅包含其中关键笔的嵌套子部件，并约束单笔回退。目标与实际关键笔功能必须有明确兼容证据；自然轻微斜度使用宽容带，不要求精确角度相同。

其他原有羊、土、王、子、车规则继续独立执行。未注册类型明确列在未验证范围中，不把空检查列表宣传为全面语义通过，也不将未注册部件全部拒绝。

### 失效与重试

准备阶段撤销不兼容的继承计划，仅把相关范围还原为参考起点，保留其他供体和放置。沿现有候选扩展重新检索；不以“该范围已经覆盖”为理由保留错误来源。发布前再次核对最终完整部件语义；生成日志保留被撤销的继承来源、复杂笔画不合格角色、候选几何拒绝及最终来源。

- 正：走底来源被撤销；址的完整止部符合语义，但由于引入跨部件碰撞被原门槛拒绝，最终采用其他合格完整/单笔来源，顶横保持原样。

验证合并字体沿用原全库与字母、符号，仅更换孔、正的生成候选，其余 10728 个候选的记录、资源、度量、来源摘要保持。字体名明确标为“v6.2 exp 验证合并版 · 孔正重生”，不是 9574 字全库 v6.2 重生成。原字体与既有文档冻结资源不更新、不覆盖。

独立新字体采用新 package/release/candidate 身份，并记录父字体及被替换候选；字体版本 0.2 表示本次内容修订，格式仍为 1.0。源字体及新字体均完整校验后，以禁止覆盖的方式发布。存在多个生成样本时，修订 API 要求明确候选选择，不会将多个样本隐式合并。
