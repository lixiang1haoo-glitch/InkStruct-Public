# v6.1 exp：从零开始的推荐采集字表 v1

本轮交付一份独立、可复现的冷启动字表，复用现有贪心采集规划器和当前 v6.1 公开结构准入函数。推荐从 **32 个字、每字 1 次**开始，采后建档并检查实际生成，再决定是否继续第二、第三批。96 字是扩展预算，不是要求新用户一次写完，也不是获得良好全库生成的保证。

## 采集文件

目录：`configs/collection/starter_v61_v1/`。

| 文件 | 用途 |
| --- | --- |
| `stage_1_32.csv` | 第一批 32 字，每字 1 次，270 笔 |
| `stage_2_32.csv` | 第二批新增 32 字，每字 1 次，276 笔 |
| `stage_3_32.csv` | 第三批新增 32 字，每字 1 次，258 笔 |
| `recommended_96.csv` | 三批合集，96 字，804 笔 |
| `validation_16_do_not_train.csv` | 可选验证采集，16 字、129 笔；本轮禁止建档或调参 |
| `split.json` | 训练与验证字符隔离清单 |
| `plan_summary.json` | 参数、输入/代码哈希、结构版本、筛选及预计结果 |

**按批导入与导入合集二选一，不要重复导入。** CSV 使用 UTF-8 BOM，与现有采集器的 `character,repeats` 列兼容。`components` 和 `reason` 逐字解释服务部件、目标示例及预计新增机会。部件名称采用结构库规范身份，例如“水”可能对应三点水，“言”可能对应言字旁，并非要求额外录制这些部件。

第一批顺序：

石、米、调、提、困、清、停、大、药、银、暗、远、怪、急、秋、阴、跑、容、疗、雷、简、浅、妈、狂、现、皆、对、何、示、去、轻、前。

单次采集用于降低首次负担。它无法估计同字书写波动，不代表一次必然映射成功。先检查坏样本和高价值缺口，再定向补录或增加实例，不默认让所有字重复五次。按本人自然写法书写，不临摹参考字体；保留完整点列、压力和时间，不平均轨迹。遇连笔或笔数差异应保留记录并审查映射，不为过关强制改写个人笔形。

## 选择范围及方法

- 目标范围是项目现有常用清单的 584 字，不是外部词频榜，也不是全部 9,574 字。固定 16 字作为未来新用户的可选跨字验证集，其余 568 字用于规划；未读取任何个人采集数据。
- 规划前按固定哈希规则划分；验证字符及其所有重复样本不作为采集候选，也不参与选字评分。选字冻结后才检查其公开结构上的复用机会。还没有新用户验证原稿，不能称为已经通过新留出测试。
- 候选限定为上述规划字中 1–16 笔、没有结构警告的 504 字。64 字因结构警告或超过笔数预算排除，不表示这些字不能生成或不值得后续采集。
- 来源与目标都使用已有可靠嵌套视图和 `author_reuse_no_split_v1`，保留完整根/父部件；不计入尹拆成一与尸的迁移机会。目标使用现有参考修正层及统一等比字框。
- 复用当前 `correspondence` 的身份、笔数、置信度与有序等比参考匹配检查，以及位置关键笔形检查。这里检查的是公开参考，作者实际形态尚未知；没有把参考点伪装成作者档案。
- 候选跨上下文复用不一概禁止。完整根节点、父部件和整字目标通道均纳入机会核对。非等比变换和关键笔替换本轮不作覆盖预测。
- 完整部件机会按目标笔画去重，权重为 1；作者单笔回退的参考类别机会权重仅为 0.2。第二个不同供体字的边际收益为 0.15，再除以采集笔数的平方根。复用 `recommend.greedy_marginal_order`，不另写选择框架。
- 计分不包含同字直接复用，不以采集一个字就“覆盖这个字”来夸大跨字收益。完整部件覆盖优先于单笔类别机会，但此启发式权重尚未由新用户质量实验验证，不宣称全局最少。

## 预计收益与书写负担

下表统一以规划集的 4,547 笔为分母，数值为“至少存在一个通过公开结构检查的跨字完整部件来源机会”的目标笔画数，不是实际采用数，也不等于能够完整生成的字数。

| 累计采集 | 采集笔数 | 推荐清单部件机会 | 原常用表同字数前缀 | 原常用表相近笔数前缀 |
| --- | ---: | ---: | ---: | --- |
| 32 字 | 270 | 2,340 / 4,547（51.5%） | 1,086（32 字、154 笔） | 1,399（48 字、268 笔） |
| 64 字 | 546 | 2,943 / 4,547（64.7%） | 1,631（64 字、377 笔） | 2,050（87 字、543 笔） |
| 96 字 | 804 | 3,234 / 4,547（71.1%） | 2,105（96 字、613 笔） | 2,417（118 字、801 笔） |

基线来自同一候选集、相同划分与检查方法，按现有常用清单原顺序取前缀；它不是专门优化过的竞争方案。相近笔数对照取不超过推荐清单笔数预算的最长前缀。推荐方案在该结构代理指标上更有效，但比同字数基线更费笔；笔数也不是实测书写时长。

前三档的边际新增完整部件机会分别为 2,340、603、291 笔，体现收益递减。因此产品应提供“先录 32 字，生成查看，再补缺口”的流程，而不是固定强迫用户写 96 字。

单独排除已推荐采集的目标字后，三档未采字的部件机会分别为 2,242/4,277、2,617/4,001、2,607/3,743 笔。此处目标集合随采集量变化，不能拿绝对数直接判断第三档退步。

冻结后的 16 字公开结构检查得到 65、76、81 / 129 笔完整部件机会。该结果没有参与重新选字，只是规划检查，不是作者风格或生成质量成绩。

## 必须保留的证据边界

当前实际新增作者样本为 0，实际可用覆盖为 **未知**。结构机会的并集可能包含不能同时放置的重叠部件，因此连完整部件机会也不是可直接兑现的覆盖率。

采后还需检验：可靠映射、作者实际位置变体、候选排序与截断、完整部件实际变换、接触关系、碰撞及自然圆弯。单笔类别机会尤其宽松，不能把它与部件机会合并后得到的高百分比宣传为“作者轨迹覆盖”或“生成准确率”。原有内部交叉不自动视为缺陷。

未覆盖的长尾、罕见字、同字多样性、压力/时长风格均未由本轮解决。新用户的用途若偏向专业术语或繁体字，应更换目标集合重新规划，不能直接套用本清单。

## 采后与产品接入

1. 导入首批 CSV，完整采集并保存原始数据。
2. 用当前 v6.1 exp 独立建档，明确排除验证字符的所有样本。CSV 的用途列只是提示，采集器不会自动执行建档隔离。
3. 报告有效映射、真实入库、生成实际采用及参考回退数量；把没有供体、映射失败、候选拒绝和放置失败分开。
4. 检查代表性整字、连接、折角、短钩和圆弯，再以实际缺口重新安排下一批。静态第二/三批是离线备用，不覆盖个性化补采建议。
5. 可选采集独立验证表，与新用户原稿比较；在本轮质量评价结束前不得混入建档。完成验证后若用于生产扩库，应另建版本并明确它不再是留出数据。
6. 作者来源不足但协议有效的生成字仍可按已修订的应用策略使用，提示参考回退与个性化不足，不把补录作为使用的硬门槛。

本轮未修改生产默认、采集器界面、原始协议或旧档案。应用后续可将第一批作为“推荐入门”入口，但本轮交付的是离线 CSV 和规划工具，尚未接入新用户引导界面。

## 复现与验证

```sh
.venv/bin/python scripts/plan_v61_starter_collection.py \
  --output configs/collection/starter_v61_new_run \
  --audit artifacts/v61_starter_collection_new_run
```

输出目录必须不存在；不会覆盖旧结果。需已有冻结公共结构数据库及参考修正上游文件。完整供体—目标证据在 `artifacts/v61_starter_collection_20261014/run_verified/`，由 Git 忽略；CSV、规划器和公开汇总可提交，不含个人笔迹。

验证包括规划拆分、重叠部件去重、禁止同字自用计分、分档一致性、真实“尹”禁止拆分与“羊”位置变体、原规则保护测试。另使用当前采集器的真实 CSV 解析器读取全部五份字表，检查次数、顺序、分档并集和训练/验证隔离。静态检查与测试成功只证明交付和规划规则符合预期，不证明生成观感已改善。
