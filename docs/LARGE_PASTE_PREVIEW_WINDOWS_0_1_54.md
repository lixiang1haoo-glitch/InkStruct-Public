# InkStruct 0.1.54 大量粘贴预览实测

从现有 Windows 0.1.54 源码接续。版本号仍为 0.1.54，本轮交付源码与验收材料。

## 输入和口径

- TXT 为下载目录中的 `InkStruct-生成支持的全部汉字.txt`，单行 9,574 个互不相同的汉字。SHA-256 为 `e3d33c511ef4e234395a9881422c86f85ebafd2829cdd9adc4f425710d7f4062`。
- 恢复文件 `71525b3ddfe614ea-3cf533f1949145d187d7d32714741e65.inkdoc` 的源码与 TXT 字节相同。其字体身份与库内 `user_001-full-candidate-count-validation-8` 相符，字体核心哈希为 `990a5e55986ab411de9c0dd128f88c63dcbae1f525e0cd508368ec11f907daee`。复用恢复文件的四张循环 PDF 页面、自定义模板、正文样式和纸张配置。现场截图的窗口尺寸和缩放没有从恢复文件确定，实验统一使用 1400 × 850 逻辑像素和 100% 缩放。
- Windows 11 原生 Qt 窗口，设备像素比 1.5，Core Ultra 5 250KF Plus，18 个逻辑处理器，约 24 GiB 可见物理内存。使用 QTest 驱动 Ctrl+V 和原生绘制事件；不使用离屏结果代替首屏。内存为 InkStruct 主进程的采样工作集峰值，另在 JSON 中记录私有提交量和 Windows 进程历史峰值。后台栅格进程与系统总内存不计入主进程指标。
- 输入恢复时间从触发粘贴到下一次零延迟 UI 回调。绘制终点为当前修订、目标页在可见窗口内且缓存的栅格实际由 paintEvent 绘出。逐组两次，第一次为同进程的首轮粘贴，第二次为暖复测。启动空白文档已完成原有文件检查，约 6.5–6.7 秒单独记录。未清除 Windows 文件缓存。基线 9,574 不同字只跑一轮，135 秒尚未到达校验，随即结束观察。

原始字表基线在读取全部候选的阶段一直未返回。按需读取后，解析约 45–56 毫秒，原有符号准备约 0.34–0.35 秒，选中汉字的轨迹读取、解压、校验和构造仍约 39 秒，计在排版函数内部。准备截断样本并排出稳定首页约 4 秒，发布给画布后约 0.8–0.9 秒完成栅格绘制。完整排版在 200 万路径点预算处明确终止，因此两份 9,574 字输入都只有首页，页数未确认，严格 SVG 保持关闭。八字重复对照显示了分阶段显示的代价，得到可见首页的同时，拒绝报告约慢 1 秒并增加约 0.1 GiB 工作集。

局部编辑的主要收益来自避免重读全部候选。逐候选对照重新读约 9,300 份候选，耗时 15.8–16.7 秒。按需路径只额外读取极少量新的汉字轨迹，正文排版仍约 2.2 秒。现场四页模板走按正文框分页，现有前后部续排在该分支禁用，两组均复用零页。普通页面另做了同样的局部编辑对照。现有续排缓存三次因预算跳过保存，复用零页。开启时排版 2.03–2.14 秒，关闭时 2.02–2.03 秒。样本未显示续排收益，本轮未扩大缓存或增加续排机制。含脚注、表格和自定义模板的完整快照保留原协调路径。

## 接入边界与正确性

- 核验库内记录的文件标记与实际文件一致后，复用原全包成员校验后的索引。大文档用索引选择汉字候选并优先匹配冻结选样，再读取与校验选定成员。既有资源可能改变候选合并顺序时沿用原路径。其他符号、样式选择、损坏字体处理和显式完整校验继续使用现有规则。
- 单独复用的轨迹缓存上限为 64 MiB、4,096 项。当前文档仍持有实际使用及历史冻结的笔迹。按需路径保存实际读入的字形，旧文档的已嵌入资源继续携带。重开可离线重现已保存的选样，读取原字体中未嵌入的候选需连接原字体包。字符校正普通查看从索引显示样本位置，提交整字符校正时才读取该字的候选。
- 只在可证明稳定的单段纯汉字场景尝试早发首页。用真实节点身份和相同版式排一段前缀，只有前缀最后一个字符已在后页时才提交首页。带复杂内容继续等待完整快照。提前页只进入画布，修订变化即作废，不能用于点字、校正或严格导出。
- 以同一批源码身份核对 2,060 字真实子集、普通页和包含跨页表格、公式、脚注的 PDF 模板。前后页序、坐标、逐笔数据、诊断、来源警告及冻结选样一致。真实子集提前页与最终首页完全相等，有缺字因此严格 SVG 维持阻断。可导出的普通页与复杂页共八页，严格 SVG 逐页一致，保存重开后再次核对一致。
- Windows 原生脚本验证了计算中继续输入、撤销、连续粘贴、迟到首页拒绝、暂定页不能导出以及最终页数恢复。大文档用真实字表和真实字体验证，超限场景不宣称完成整篇 SVG。
- 初次 383 项回归有 381 项通过，两处旧失败均用已交付 0.1.54 EXE 内的原模块复现。文档上限诊断现在直接显示于状态栏，该测试已通过。另一项旧测试在异步 SVG 导出刚开始就读取目录，失败原因留在 `prior-release-tests.log`，最新专项 122 项通过，覆盖实际后台 SVG 导出。

## 复现

在项目根目录执行，输出目录须为空的新目录。验收脚本使用现有字体和恢复副本，只读访问。

```powershell
$env:PYTHONPATH = (Resolve-Path src).Path
$env:QT_QPA_PLATFORM = 'windows'
$e = 'artifacts/large_paste_0.1.54'
.venv/Scripts/python.exe -B -X utf8 "$e/benchmark.py" "$e/recheck-unique" unique
.venv/Scripts/python.exe -B -X utf8 "$e/benchmark.py" "$e/recheck-repeat" repeat
.venv/Scripts/python.exe -B -X utf8 "$e/benchmark.py" "$e/recheck-edit" edit
.venv/Scripts/python.exe -B -X utf8 "$e/benchmark.py" "$e/recheck-rich" rich
.venv/Scripts/python.exe -B -X utf8 "$e/benchmark.py" "$e/recheck-eager-edit" edit --eager
.venv/Scripts/python.exe -B -X utf8 "$e/check_correctness.py" "$e/recheck-correctness"
.venv/Scripts/python.exe -B -X utf8 "$e/native_revision.py" "$e/recheck-revisions"
```
