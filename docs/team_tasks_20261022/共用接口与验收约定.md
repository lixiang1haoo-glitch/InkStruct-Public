# InkStruct 两组共用接口与验收约定

发布日期：2026-10-22。适用对象：组长、字集研究与评测组、Android 开发组。

本附件定义任务下发、移动录制、批次接收、评测与实机检查之间的边界。`handwriting_single_v1` 和基础 CSV 是已有兼容入口；下述 `plan.json`、批次清单、压力旁附记录和自动验收适配是本轮新增要求，尚未成为生产协议。两组在 M0 用最小文件包联调并固定字段和测试；必要变更记录版本、理由和兼容方式，由组长维护公共约定。

## 一 基线与数据身份

- 当前桌面应用版本为 0.1.40，唯一来源 `src/inkstruct/fonts/__init__.py` 的 `APP_VERSION`。研究默认生成方式显式指定 `v62`，当前工作流版本为 `desktop-semantic-v62-20261020.1`。重新发应用构建时由组长递增应用版本，至少 0.1.41；本次任务文档不构成应用构建。
- Git 提交加未提交快照才构成当前源码。基线清单记录实际 HEAD、工作树文件哈希、结构库逻辑身份、修正规则、字表目录、参考资源、依赖版本与样本批次。
- 公共目标为完整一级 3500 字 T，S 为与基线结构库支持成员的交集，U 为缺口。T 保留原表顺序，派生集不冒称现有内置集合。所有目标、候选和实验划分保存实际字符与哈希。
- 第一阶段生成、参考展示和评测使用同一修正结构定义。现成笔顺导出脚本默认直接读原始结构仓库，不自动等同于修正后的应用视图；组长提供一致参考包，Android 组负责展示坐标变换。
- 作者 ID 为稳定的内部身份，显示名称可以重复。沿用组长提供的已有 ID；新作者使用符合桌面约束的 `w_` 加 UUID 十六进制串。设备 ID 不冒充作者 ID。

## 二 录制任务交换

任务 ZIP 使用相对 POSIX 路径，包含 `plan.json`、`characters.csv` 及可选 `references/`、`LICENSES/`。附件与 CSV 文件保存 SHA-256 清单；相同方案版本的字、顺序、份数、用途和文件内容不可变，修改后递增方案修订号。

CSV 最低列为 `character,repeats`，UTF-8 BOM，按行顺序录制，每个字符一行；`repeats` 为 1 至 100 的整数。拒绝字符重复的任务表，要求提供者先合并份数；不静默去重。每个任务最多 50000 份，CSV 最多 2 MB，与现有桌面预检查对齐。新增可选列为 `purpose,components,reason`，移动端可展示但不能据此改变原字符。

一个任务只包含一种用途：`training`、`development`、`validation` 或 `smoke`。正式验证字的归属以冻结的字符划分为准，不能只信 CSV 标签。两组分开下发训练和验证任务，避免普通递归导入混入验证数据。

`training` 任务中的录制字必须属于合格推荐候选；`development` 和 `validation` 任务按对应冻结划分检查成员，不要求属于训练候选。`smoke` 是协议和功能检查，不能进入正式质量统计。

新增 `plan.json` 至少包含以下信息，具体 schema 字段名在 M0 首轮联调固定：

| 字段 | 类型与含义 | 维护方 |
| --- | --- | --- |
| `schema_version` | `inkstruct_collection_plan_v1`，本轮拟定格式标识 | 两组与组长 |
| `plan_id`、`revision` | UUID 字符串、从 1 起的整数；标识不可变方案修订 | 字集组 |
| `name`、`purpose` | 显示名称与上述单一用途 | 字集组 |
| `target_set_id`、`target_version` | 明确为一级字表派生集及 2013 原表版本 | 字集组 |
| `target_characters`、`supported_characters`、`unsupported_characters` | 实际有序字符数组；后二者严格分割目标 | 字集组 |
| `candidate_characters` | 实际候选数组；首轮为 S 的子集，排除留出字 | 字集组 |
| `structure_identity`、`reference_identity` | 与组长冻结基线一致的身份 | 组长提供，两组校验 |
| `csv_path`、`files` | CSV 相对路径；全部附带文件的 SHA-256 映射，不含 plan 自身 | 字集组；Android 校验 |
| `split_id`、`selection_version` | 冻结实验划分及推荐方法版本；smoke 用途可为空并明确原因 | 字集组 |

plan 只描述录制方案，不预先绑定作者；作者在 task 创建时绑定。验收先校验方案，再校验执行任务与样本归属。

字符数组哈希统一按有序字符直接拼接后的 UTF-8 字节计算，不加 BOM、分隔符或末尾换行；逐文件哈希按原始文件字节计算。不进行简繁转换或 Unicode 归一化。

`plan_id` 标识推荐方案，`task_id` 标识某位作者在某设备上执行的一次任务。Android 创建 task 时绑定 plan 修订、作者和输入模式；每个字符及份次生成稳定 `item_id`。重新录制产生新 `sample_id`，保留 task、item 和修订关系。重复导出保留同一组 ID；跨设备重新录制新建 task，不在首版合并活动进度。

## 三 已有原始样本协议

桌面 `samples.load_raw_sample` 现有硬约束如下，成员需以实际代码复核：

- `schema_version="handwriting_single_v1"`；`writer_id` 非空且与导入作者一致。
- `character` 是一个 Unicode 码点；若有 `codepoint`，必须匹配 `U+XXXX`。
- `capture.canvas_width/height` 为有限正数；样本有笔画，每笔至少两个真实点。
- 每点 `x/y` 有限且在本地画布范围内，`pressure` 在 `[0,1]` 内；缺省压力由现有读取器按 0.5 处理。
- `t_ms` 可转整数且跨所有笔画全局单调不减。新增 Android 导出进一步要求为非负整数，首个有效点为 0。
- 顶层 `task` 等扩展可保留在原 JSON 中，但现有索引模型不保存所有顶层扩展；整个 `capture` 字典会保留。

因此，本轮需进入索引的采集身份信息统一写入 `capture`，并在顶层 `task` 保留兼容副本；接收器校验重复字段一致。下例仅为可通过读取器的合成协议样例，既不是实采证据，也不得加入研究或用户档案：

```json
{
  "schema_version": "handwriting_single_v1",
  "sample_id": "smoke-example-only",
  "writer_id": "w_smoke_fixture",
  "character": "一",
  "codepoint": "U+4E00",
  "task": {
    "task_id": "00000000-0000-4000-8000-000000000001",
    "item_id": "00000000-0000-4000-8000-000000000002",
    "repeat_index": 1,
    "repeat_total": 1
  },
  "capture": {
    "canvas_width": 640,
    "canvas_height": 640,
    "device_pixel_ratio": 1.0,
    "coordinate_space": "logical_px",
    "input_type": "finger",
    "pressure_available": false,
    "pressure_mapping": "constant_0.5",
    "time_origin": "sample_first_valid_down",
    "clock": "monotonic_event_time",
    "duration_ms": 100,
    "purpose": "smoke",
    "synthetic_fixture": true,
    "task_id": "00000000-0000-4000-8000-000000000001",
    "item_id": "00000000-0000-4000-8000-000000000002",
    "repeat_index": 1,
    "repeat_total": 1
  },
  "strokes": [
    {
      "stroke_index": 0,
      "points": [
        {"x": 100.0, "y": 320.0, "pressure": 0.5, "t_ms": 0},
        {"x": 540.0, "y": 320.0, "pressure": 0.5, "t_ms": 100}
      ]
    }
  ],
  "stats": {"stroke_count": 1, "point_count": 2}
}
```

真实 Android 样本的 `capture` 还应包含 plan 身份与修订、`split_id`、`session_id`、设备型号与 Android 版本、采集应用版本、书写区像素与方向、压力来源与映射参数、参考身份及创建时间。`input_type` 使用 `stylus` 或 `finger`；用途不可自动改变。`duration_ms` 表示有效点时间跨度，主动操作、暂停和重录成本另外记入会话记录。

原始坐标是书写区像素，不是生成协议的 `[0,1]` 坐标。兼容压力可归一化，实际事件原压力与可选倾角等完整数据放旁附 JSON，使用 `(sample_id,stroke_index,point_index)` 对齐；不要只在 point 中加字段后假定现有索引会保留。压力不可用时旁附可记录系统原值，但不将其标为可信测量。

## 四 导出批次与接收

新增批次格式拟为 `inkstruct_android_capture_batch_v1`。Android 组实现导出、清单校验和活动样本提取，字集组在此基础上实现字符分组与研究索引；组长维护接入生产的决定。目录约定为：

```text
batch.zip
  manifest.json
  plan/plan.json
  plan/characters.csv
  samples/<sample-id>.json
  raw-events/<sample-id>.json
  history/<retired-sample-id>.json
  reports/session.json
  LICENSES/...
```

`manifest.json` 记录 batch UUID、schema、作者、任务与方案身份、实际采集 app 版本、活动样本列表、旧样本替代关系、全部成员文件的哈希和计数。manifest 不自包含哈希，ZIP 整包哈希在交付清单中另列。历史样本保留但不进入活动样本列表；文件路径是相对路径，禁止绝对路径、上级跳转和重名成员。

同一次批次快照的重导出可保留 batch ID；内容变化必须创建新 batch ID。已存在样本 ID 且内容相同视为重复接收，不重复计数；相同 ID 不同内容视为冲突，隔离并报错。任务完成数按活动样本集合调和，不能只相信独立计数器。重录的旧样本与新样本同属一个 item，研究可用集合只取声明的活动版本。

接收顺序固定：校验清单与哈希 → 解到全新隔离目录 → 逐个读取活动样本 → 检查作者与任务身份、修订关系及重复 → 按冻结字符划分训练／开发／验证／未计划 → 从合法分组生成新的导入目录或索引 → 明确执行研究建档。

现有 `extract_new_batch` 只完成部分 ZIP 检查，`partition_samples` 只完成批次内去重与字符分组；新增清单、跨批次幂等和修订处理需开发。现有 `import_samples` 会递归扫描 JSON 并替换指定作者目标索引，不适合直接接收整个 ZIP 根目录。中间文件、原始事件、历史样本和验证原稿均不应被整包递归导入。

## 五 共同验收

| 验收项 | 实施方 | 必备证据 |
| --- | --- | --- |
| 正常任务包、损坏哈希、重复字、非法份数、未知参考 | 字集组提供例子，Android 组执行 | 明确接受或拒绝结果，错误不创建半完成任务 |
| 合法样本、坐标越界、倒退时间、压力缺失或映射、作者冲突 | Android 组导出与检查 | Python 读取结果、原事件对照、失败记录 |
| 恢复、重复接收、重录和验证隔离 | Android 组接收适配，字集组分组验证 | 活动集合、索引计数和修订历史一致，重试不改变有效数量 |
| 原点、笔数、时间、压力和来源往返 | 两组联调 | 原 JSON 与导入索引逐点比较；额外通道按旁附清单比较 |
| v6.2 未录字生成 | 字集组运行，组长复核 | 真实 method、引擎与资源身份、逐字来源、失败及回退报告 |
| 写字机输出 | 组长运行，两组负责对应问题 | 测试包、机器参数、照片或视频、问题记录和回归结果 |

协议测试可用合成固定样例；采集真实性、设备能力和质量结论必须使用真实录制数据。基础读取成功只是一个检查项，不能替代完整任务一致性、结构合法性和人工质量评价。

本附件只提供当前可执行的样本读取自检例子，假定已取得新解压出的单作者活动样本目录；不包含未来接收器命令：

```powershell
.venv/Scripts/python.exe -B -X utf8 -c "from pathlib import Path; from inkstruct.samples import load_raw_sample; root=Path('artifacts/team-smoke-NEW/active-samples'); files=sorted(root.glob('*.json')); assert files, '没有活动样本'; values=[load_raw_sample(p, expected_writer='w_smoke_fixture') for p in files]; print('validated', len(values))"
```

真实数据改成实际作者与新目录。不能据此对生产索引做覆盖导入。当前 `scripts/verify_application_generation.py` 包含 v4／v6.1 及方法名断言，不是直接可用的 v6.2 验收脚本；两组需另做显式适配。

## 六 写字机测试包

组长保管硬件。成员提交测试前完成数字检查，包内包括：测试 ID、输入与样本或生成结果身份、严格机器 SVG、预览、目标物理尺寸、路径与抬落笔统计、建议参数、预期表现和待确认问题。严禁把带无效路径的草稿当成可执行机器文件。

组长返回实际设备、笔与纸、控制软件、速度等参数，照片／视频和问题编号。字集组负责分析字形、风格和推荐策略相关问题，Android 组负责采集与数据问题；生成或机器控制问题由组长处理。机器测试可按固定窗口集中安排，日常研究和移动端开发不以硬件在线为前提。
