# InkStruct 字集研究与评测组任务书

发布日期：2026-10-22。接收人：字集研究与评测组两名成员。项目统筹、生成主线和写字机实测由组长负责。

本组负责研究：以大陆常用规范汉字为生成目标时，用户应先录哪些字、各录几份，以及何时继续补录，才能在可接受的录制时间内取得较好的未录字生成效果。最终交付可执行的录制方案、可复现实验与有明确适用范围的评价结论。

本任务书与[共用接口与验收约定](共用接口与验收约定.md)一起下发。接口附件中的新增交换格式是本轮开发要求，现有程序尚未实现完整支持；本组与 Android 组在 M0 联调时共同落实。

## 一 目标与范围

1. 首要目标集采用 2013 年《通用规范汉字表》一级字表 3500 字，从当前内置 `cn-tgh-2013` 的原序 0001 至 3500 提取，保留来源与成员哈希。首轮推荐候选限定在该目标集内。
2. 原始目标记为 T，当前结构库支持的目标记为 S，不支持部分记为 U；必须完整报告三者。可运行实验在 S 内进行，不把 S 的结果表述为完整 T 的效果。
3. 区分冷启动方案与已有作者的增量补录方案。已有合格供体继续保留，目标集缩小不意味着过滤已有供体；评测留出字的全部样本则必须排除。
4. 比较录制更多不同字和对关键字重复录制的收益；同时计量字数、总笔画、实际耗时、重录率和最终可用样本量。
5. 第一阶段固定当前 v6.2 生成基线。推荐策略变化和生成引擎变化分别实验，不在一次对照中同时改变。

一级 3500 字、全表 8105 字和 GB2312 汉字集是不同集合。当前完整 8105 字的支持数为 6866、缺口为 1239；一级字表的支持数需重新核算。字表范围参见[教育部说明](https://www.moe.gov.cn/jyb_xwfb/s271/202009/t20200915_488073.html)，项目现状参见[0.1.40 记录](../RELEASE_0_1_40_WINDOWS.md)。

本组不修改生产生成核心、公共样本协议或默认推荐入口。必要改动先在独立研究目录实现并提出集成建议；集外候选、繁体字集和神经模型训练列为后续扩展。

## 四 工作方法与接口

本组向 Android 组提供 `characters.csv`、`plan.json`、目标与候选成员、份数、用途和版本。旧 CSV 的最低兼容列为 `character,repeats`；详细字段和哈希规则见接口附件。录制方案的推荐分数和理由放在旁附报告，不要求移动端实现推荐算法。

本组接收 Android 的完整导出批次，先校验、按字符划分并隔离验证数据，再建立研究用索引。不能把导出 ZIP 根目录整体交给递归 import。接收端须读取完整 `capture` 元数据；输入方式、压力有效性和修订状态不得在评测中丢失。

实验至少包含随机选择、已注明语料来源与版本的频率优先、现有结构覆盖、新方案四类；现有冷启动策略可作为第五类。推荐器之间使用相同合格候选池和份数规则，随机策略至少三个固定种子。公共字表原序不是字频排序。

先以相同字数比较，再用相同笔画预算和实测时间比较。历史样本缺少耗时信息时，明确标为代理成本；小规模新录制需记录主动录制时间、暂停时间、重录时间。用相同作者、输入方式和目标作配对比较；设备书写顺序做轮换，减少熟练度与疲劳影响。

冷启动预算分别记录不同字符数与实际份数；增量实验固定同一个初始合格档案，预算只计算新增录制。重复份数消融按总成本比较，不能把每字多录数份与单份录制视为相同工作量。

开发集用于调方案；最终验证字符在调参前固定并留存哈希。其所有重复样本及在其他批次中的同字样本全部从建档和供体检索中排除。验证原稿的几何与评分在选字及生成结果冻结后使用。额外检查记录与逐笔来源，证明没有混入留出字。

评价分开报告：笔数笔顺和内容错误、真实作者来源覆盖及参考回退、协议与几何诊断、风格相似度、整体可接受性，以及录制成本。每项明确分子分母；失败、无法对齐和未支持目标单列，不只统计成功输出。作者先分别统计，再给作者等权汇总；同字重复和同作者数据不能冒充独立作者数。

现有盲评工具可复用展示与收分部分。正式对比每条至少三位未解盲独立评分者；提供同一作者的非留出风格参照，并分开问内容、风格与整体接受度。置信区间和比较方式在 M0 固定，按作者与字符的分组结构统计；不能直接用旧评分器的既定门槛代替本研究结论。

## 五 阶段交付与验收

按顺序通过 M0 至 M3。M0 由本组列出负责人、计划日期、数据缺口和计算预算，与另一组对齐；新增数据不足时先完成试验，不把不足样本的结果称为完整验证。

| 阶段 | 必交付物 | 通过标准 |
| --- | --- | --- |
| M0 基线与实验计划 | T／S／U 清单、输入与源码身份、留出划分、指标口径、资源清单、任务接口样例 | 可重新提取 3500 字并解释缺口；确认真实 v6.2 调用；冻结预算、评分与验证划分 |
| M1 小样本闭环 | 至少一位作者的 16 至 32 字录制任务、单独验证任务、Android 接收报告、v6.2 适配脚本和小型结果 | 从移动录制到未录字生成可复现；验证字无供体泄漏；每项失败有原因；合成样例不作为质量证据 |
| M2 对照实验 | 默认以至少三位作者、32／64／96 字预算、每位至少 32 个最终验证字开展；包含四类策略、重复份数消融和设备分组分析 | 所有方法同基线同数据条件；随机至少三种子；报告实际数量、缺失和排除；已完成盲评及成本统计 |
| M3 定稿与交接 | 起步档、推荐档、补录档 CSV 与方案清单；可执行脚本、逐字结果、图表、盲评报告、适用边界和操作说明 | 另一成员能从新目录复跑关键比较；Android 可加载任务；新增策略即使无提升也有可信结论；集成由组长决定 |

M2 数量是本任务的默认实验规模，不代表统计充分性或生成质量保证。若数据不够或预算不可行，在看最终结果前修订计划并记录；仍需区分试验完成与正式结论。不得为“证明有效”在解盲后换字、换作者或改指标。

## 六 最终提交清单

- 代码、配置、环境依赖、运行命令、源码与数据哈希，以及失败重跑方式。
- `targets`、`splits`、`plans`、`runs`、`metrics`、`blind-ratings` 的清晰目录；评分映射单独保管。
- 每档增量与累计任务分开，明确导入方式，避免重复录制；每个推荐字提供成本和服务目标说明。
- “录制时间与质量”“笔画预算与质量”曲线；分作者、分输入方式的原始统计与缺口列表。
- 问题清单包含严重度、复现步骤、样本 ID、引擎版本和相关文件，不能只交截图。

建议独立目录为 `scripts/collection_research/`、`configs/collection/research_v1/`、`tests/test_collection_research_*.py`，实验结果放新建 `artifacts/collection_research/<run-id>/`。这些目录是本轮建议布局，并非现有实现。不得覆盖原始样本、历史结果、作者档案、评分或发布包。

每周至少一次两组联合检查，平时直接交换接口问题；周报只需说明已完成证据、主要结论、阻塞和下一交付。需要写字机时提交接口附件规定的测试包，组长负责实测，本组负责分析与回归。
