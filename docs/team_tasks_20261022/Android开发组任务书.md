# InkStruct Android 开发组任务书

发布日期：2026-10-22。接收人：Android 开发组两名成员。项目统筹、桌面生成主线和写字机实测由组长负责。

本组开发可离线使用的 Android 录制程序，优先支持平板配套笔、平板手指和手机手指三种场景。交付重点是可靠采集与导出真实单字轨迹，使样本能进入现有桌面导入、建档和生成流程。

本任务书与[共用接口与验收约定](共用接口与验收约定.md)一起下发。首版完成汉字采集；字母符号、跨端继续同一活动任务、账号和云同步不列入本次验收范围。

## 一 功能目标

1. 导入字集组提供的任务包，预览作者、任务字数、份数、用途和缺口，确认后创建任务。
2. 显示当前字、进度、标准笔数和下一笔参考；支持撤销上一笔、重写、保存、暂停、恢复和重录。
3. 采用同一套采集与存储内核适配三种设备场景，提供清晰的笔模式和手指模式。手机书写区、按钮和边缘手势需单独检查。
4. 样本提交后可靠落盘；被杀进程或重新打开后恢复任务。保存失败不增加完成数，重录保留旧样本和修订关系。
5. 导出 ZIP 批次及完整性清单，桌面端可检验并提取活动样本。首版以文件交换完成离线闭环。

技术方案以 Kotlin 原生 Android 为默认方向。Compose 或 Views 由本组在 M0 根据原始事件与画布原型选择，记录选择依据。Android 最低版本、目标 SDK、JDK、构建工具和首批支持机型在 M0 按设备库存固定；不能用模拟器代替真实笔、手指和误触验收。

## 四 输入与数据要求

原始样本必须记录收到的实际采样事件，包括历史点、落笔和抬笔端点。显示可使用平滑或预测改善观感，但预测、插值和简化点不得写入原始轨迹。不要先拟合曲线再导出为“原始点列”。

笔模式根据 tool type 与 pointer ID 跟踪笔，手掌和手指不成为书写笔画；手指模式按明确的单指规则处理，多指不能合并为一条轨迹。处理 `ACTION_CANCEL` 和系统取消标记时，撤销对应未提交笔画，不能把误触保存为有效一笔。不同 API 等级的能力在设备报告中列明。

压力只在设备与输入方式具备可信测量时标为有效。Android 原始压力可能超出旧协议范围，必须保留原始值并通过已声明规则映射至 `[0,1]`；设备报告的常量不自动证明有可靠压感。无有效压力时兼容值固定 0.5，记录 `pressure_available=false`，不得生成伪压力曲线。

时间使用单调事件时钟，`t_ms` 为该次样本首次有效落笔起的相对毫秒，跨笔全局单调不减，不随每笔归零。撤销和重写后仍以该次有效样本统一时间起点整理，不能保留倒退时间。显示、存储与导出约定见接口附件。

坐标保存为书写区本地逻辑像素，宽高和坐标使用同一空间。屏幕旋转、画布尺寸变化或切换输入模式时，应先完成、暂存或放弃当前字，禁止把不同变换下的点直接拼接。越界提示并使当前字不可作为合格样本提交，支持原稿草稿保留和重录；不得静默裁点、夹到边框或改写为范围内数据。

一笔不足两个真实点、笔数不符、取消事件和未闭合笔画必须得到明确处理。可以留作隔离草稿，不能伪造第二点或通过关闭校验把它算成完成。笔数通过不代表内容和笔顺已经正确；首版不要求自动识别全部汉字。

## 五 接口与责任

最低兼容任务 CSV 为 UTF-8 BOM 的 `character,repeats`；任务包同时包含本轮新增 `plan.json` 和参考资源身份，详见接口附件。原有 CSV 可独立导入并创建本地方案身份，但用途必须由创建流程明确选择并保存，不能把未知用途默认当作训练。

导出保留作者稳定 ID、方案版本、任务与份次、样本 ID、设备和输入方式、压力有效性、时间和坐标约定。CSV 再导入或任务恢复不得无提示创建重复工作；更换作者必须创建新任务身份。样本 ID 不因重新导出而变化。

Android 的本地任务状态与桌面活动任务内部格式分开。首版支持桌面接收样本，不承诺将 Android 任务进度直接写入桌面 `capture-management.json`。接收适配由本组实现协议检查和活动样本提取，字集组实现训练与验证划分，组长审核接入主线的部分。

## 六 阶段交付与验收

| 阶段 | 必交付物 | 通过标准 |
| --- | --- | --- |
| M0 原型与接口 | 设备清单、构建环境、架构与存储选择、事件原型、任务和样本例子、开发日程 | 至少一台真实平板笔输入可记录原始点；共用接口字段、边界与参考资源版本经两组联调确认 |
| M1 离线最小闭环 | 可安装 APK、任务导入、单字采集、保存恢复和 ZIP 导出、桌面自检命令 | 配合字集组完成 16 至 32 字小任务；合格活动样本全部通过桌面校验；v6.2 可建档并生成未录字 |
| M2 三场景与可靠性 | 手机／平板界面、手指模式、笔顺提示、撤销重录、故障测试与设备报告 | 三种场景均有真机证据；每种至少完成 32 字任务，另做 20 分钟连续使用；全部必测故障都有结果，未测项明确列出 |
| M3 交付与联验 | 源码、构建说明、版本化 APK 及哈希、自动测试、操作指南、样本包、已知限制 | 另一成员能按文档构建并安装；相同数据重复导出身份稳定；桌面接收结果可复现；字集组确认可用于实验 |

M0 给出各阶段计划日期及负责人；设备缺失时先推进可运行部分，相关模式保持待验收，不能以模拟器或相似设备报告结案。通过功能验收不以生成质量提高为前提；生成效果由字集组和主线单独评价。

必测故障与边界包括：笔加手掌、多指、取消事件、导航打断、移出再进入画布、快速点笔、横竖屏、暂停恢复、写到一半切后台和杀进程、保存中故障、存储不足、重复导入、重复导出、作者切换、损坏任务、导出失败、旧样本重录。保存确认后的活动样本零丢失、零无提示覆盖、作者零串用；未完成笔迹的草稿恢复策略需明确，恢复不得伪装成已完成样本。

性能报告列出实际设备的点数与事件统计、20 分钟会话表现、保存和恢复耗时。可报告具体测得的延迟；未经测量不能宣称固定低延迟或固定采样率。已知问题逐项给出复现条件、影响和处理方式。

## 七 提交和维护约定

建议以独立 `android/` 目录或独立仓库开发，由 M0 确认实际位置。桌面接收原型建议放 `scripts/android_receipt/`，测试放独立文件；这些是新增工作目录。不要在成员分支自行修改 `APP_VERSION` 或覆盖发布产物，统一应用版本由组长管理。Android 的 `versionName` 从组长提供的同一 `APP_VERSION` 派生，不另设硬编码版本源；`versionCode` 单调递增。首次成员交付构建前，由组长分配符合项目递增规则的新应用版本并在 M0 固定构建流程。

每次提交附源码身份、构建版本、支持设备、测试结果、导出样本和问题清单；APK 之外必须交可构建源码。各组先完成数字验收；写字机测试按共用附件提交材料，组长实测后由本组或字集组跟进定位。
