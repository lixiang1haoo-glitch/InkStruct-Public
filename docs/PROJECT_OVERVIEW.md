# InkStruct（墨构）项目介绍

InkStruct 是一个由汉字结构先验驱动的个性化在线手写轨迹生成项目。项目名称中的 **Ink** 表示用户墨迹、速度、压力和几何风格，**Struct** 表示生成过程始终由标准汉字结构约束内容正确性。

与只输出一张字形图片的系统不同，InkStruct 的核心产物是按标准笔顺组织的在线轨迹：每一笔都包含采样点坐标、相对时间、压力和笔状态，因此可以继续用于动画播放、轨迹分析、在线书写数据处理或其他需要笔画序列的应用。

> 当前生产默认实现是确定性的 `ComponentTrajectory v4 adaptive`。它可以在 CPU 上运行，不要求为每位用户训练神经网络。v5 分层残差模型属于研究与诊断路径，只有正式训练且置信度通过校准的检查点才会接管生成，否则会安全回退到确定性生成器。

## 项目目标

InkStruct 试图同时解决两个容易互相冲突的问题：

1. **内容必须正确**：目标汉字应具有标准笔数、标准笔顺、有效笔画标识和合理部件拓扑，不能因为模仿用户风格而增删笔画或偷偷替换字符。
2. **风格应可迁移**：用户不需要写完结构库中的每个字。系统应从有限样本中学习整字比例、倾斜、部件布局、部件整体轨迹、局部曲线、速度和压力，并迁移到未书写字符。

项目适合以下场景：

- 从个人单字轨迹建立可缓存的书写风格档案；
- 按指定文本生成标准笔顺的个性化在线轨迹；
- 为结构库中的全部支持字符批量生成 JSON、SVG 和 PNG；
- 根据部件覆盖缺口推荐最值得补采的字符；
- 检查笔画数、错序、低置信对齐和生成结构安全性；
- 研究结构先验、确定性生成和分层神经残差模型之间的差异。

项目当前不以以下目标为主：

- 不生成 TTF、OTF 等可安装字体文件；
- 不优化自然连笔、词级连接或整行排版；
- 不把离线图片识别为在线轨迹；
- 不修改或覆盖采集器产生的原始用户 JSON；
- 不保证对结构库之外的字符进行近似替代；
- 不把实验检查点自动视为生产模型。

## 核心思想

### 分层生成

InkStruct 不直接从字符编码预测所有点，而是沿着汉字的结构层级逐步生成：

```text
目标字符
  │
  ├─ 标准 CharacterGraph：字符、部件树、标准笔画、笔顺和关系
  │
  └─ 用户 StyleProfile：整字风格、部件布局、部件轨迹、时间和压力
          │
          ▼
整字布局变换
  → 部件整体位置和比例
  → 部件共享坐标系中的完整多笔轨迹
  → 单笔开放 B-Spline 平滑与弧长重采样
  → x / y / t_ms / pressure / pen_state 在线采样点
```

这一层级可概括为：

```text
整字布局 → 部件整体轨迹 → 部件内部笔画 → 在线采样点
```

标准结构决定“写什么”和“按什么顺序写”，用户档案决定“写成什么风格”。两者被明确分开，使风格迁移不能破坏汉字拓扑。

### 整组部件轨迹

`style_profile_v4` 使用 `ComponentTrajectoryPrototype` 保存一个叶子部件的完整多笔轨迹。部件内所有笔画共享同一个局部坐标系，因此以下信息可以整体保留：

- 各笔在部件中的相对位置；
- 横、竖、撇、捺等笔画的相对长短；
- 多笔之间的间距、穿插和整体弯曲；
- 每一笔的曲线控制点、压力曲线和持续时间。

档案同时保存跨字符聚合原型和 `字符::部件` 直达原型。用户写过目标字时可优先使用直达证据；目标字未写过时，可从具有兼容部件上下文的其他字符迁移；证据不足时则回退到更保守的布局、单笔或标准中心线路径。

### 笔顺感知对齐

用户样本和标准结构笔数相同，并不代表两者顺序相同。InkStruct 会构造标准笔画与用户笔画之间的全局代价矩阵，综合局部形状、位置、端点、方向、长度和弱顺序先验进行一对一匹配。

对齐结果分为：

- `declared`：原始顺序得到支持；
- `corrected`：非恒等排列具有足够高的置信度，按显式映射纠正；
- `ambiguous`：存在错序迹象但证据不足，不进行猜测并从局部风格抽取中隔离；
- `not_applicable`：例如需要拆笔或合笔映射，不能用简单排列描述。

原始时间和压力始终跟随对应用户笔画，不会因为调整标准顺序而与轨迹错配。更完整的算法说明见[笔顺对齐 v2](STROKE_ORDER_ALIGNMENT_V2.md)。

## 系统组成

### 结构图数据库

`structures build` 将 Make Me a Hanzi 的标准笔画中心线、字典和 IDS 拆分信息转换为版本化 SQLite 数据库。每个 `CharacterGraph` 主要包含：

- 字符、Unicode 码点、locale、拆分表达式和部首；
- 有顺序的标准笔画、标准笔画 ID、中心线和几何签名；
- 递归部件树、部件身份、字形变体、角色、布局和包围盒；
- 笔画之间的先后、相交、接触和相对位置关系；
- 数据来源、来源提交和结构置信度。

数据库是所有采集校验、对齐、建档、推荐、生成和评估共同使用的结构真值来源。

### 样本索引

`samples import` 读取兼容 `handwriting_single_v1` 的单字 JSON，对 writer、字符、画布、坐标、压力和时间戳进行验证，然后生成 `index.jsonl`。

导入过程具有以下特性：

- 原始 JSON 只读，不复制、不改写；
- 索引记录原始绝对路径和 SHA-256；
- 可接受和拒绝文件会分别统计；
- 多批索引可以去重合并；
- 同 ID 不同内容的冲突不会被静默覆盖。

因此，索引是原始数据与 InkStruct 流水线之间的不可变引用层，而不是原始数据的替代副本。

### 风格档案

`profile build` 读取索引中的样本并一次性完成标准对齐和风格抽取，输出版本化 `StyleProfile`。主要内容包括：

- 全局宽高比例、缩放、偏移和倾斜；
- 传统条件化单笔残差；
- 部件布局、字符专属布局和兄弟部件关系；
- 部件条件单笔原型；
- 整组部件轨迹和字符直达部件轨迹；
- 压力、时间、覆盖统计和被隔离样本；
- 可选的 v5 因子化风格表示。

同一份档案会写入不可变版本文件 `<profile-version>.json`，同时更新便于调用的 `profile.json`。批量生成只读取缓存档案，不在每个目标字符上重新扫描原始样本。

### 确定性生成器

确定性生成器是当前生产默认。它结合结构库和风格档案，执行整字变换、部件布局、整组部件轨迹迁移、平滑和重采样。每一笔通常输出 24–128 个节点；较长笔画获得更多节点。

组件模式包括：

| 模式 | 用途 |
| --- | --- |
| `adaptive` | 默认模式。按证据可靠性逐级使用部件层并保守回退。 |
| `off` | 关闭部件条件化，作为旧路径或 A/B 基线。 |
| `stroke` | 只启用部件笔画相关路径，用于诊断。 |
| `layout` | 只启用部件布局相关路径，用于诊断。 |
| `full` | 激进完整部件替换，用于消融，不建议作为常规默认。 |

### v5 分层残差模型

实验性学习模型包含风格编码器、结构编码器和跨注意力笔画解码器。每个标准笔画 token 对应一个输出笔画，模型预测局部 B-Spline 残差、压力、持续时间、密度和置信度。

正式训练要求：

- Python 训练依赖和支持 CUDA 的 PyTorch；
- NVIDIA GPU；
- 本地 CASIA LMDB 数据；
- 按书写者隔离的训练、验证和测试协议；
- 干净的 Git 工作树，保证正式报告可复现。

CASIA POT 数据没有真实压力和时间戳，因此当前训练只监督几何、采样密度和置信度，生成压力和时长继续来自确定性用户记忆。`training_status` 非 `formal` 的 smoke 或旧检查点在正常阈值下会触发确定性回退。

### 桌面应用

项目提供两个分离的桌面入口：

- **InkStruct Collector**：创建或导入采集任务、显示标准笔数和下一笔参考、阻止错误笔数样本保存；
- **InkStruct Generator**：导入样本、构建档案、生成指定文本或全部字符，并显示后台进度、取消状态和 CUDA 可用性。

采集器源码入口依赖仓库相邻位置的 `data_collection` 内核；`release/InkStructCollector/` 便携包已将运行时打包，不需要安装项目或 PyTorch。

### 评估和实验

评估层包含三类能力：

1. 对生成目录验证笔数、笔顺、标准笔画 ID、坐标、压力和时间单调性；
2. 按字符留出用户样本，比较标准骨架与个性化生成的几何距离；
3. 比较增量样本或重录前后的档案迁移效果。

实验层提供预算扫描、固定消融、盲评包生成和多人盲评计分。实验报告会记录配置、Git 状态、结构版本和统计结果，生产生成不依赖这些实验命令。

## 端到端数据流

### 常规生产路径

```text
TXT / CSV 采集任务
        │
        ▼
InkStruct Collector
        │ handwriting_single_v1 JSON（原始数据，只读保存）
        ▼
samples import / merge
        │ sample_index_v1 JSONL（路径 + SHA-256）
        ▼
samples audit ───────────────→ 重录 CSV → 再次采集 / replace
        │
        ▼
profile build
        │ style_profile_v4 / v5
        ├──────────────→ collect recommend / coverage-tiers
        │
        ▼
generate + CharacterGraph SQLite
        │
        ├─ manifest.json
        ├─ trajectories/U+XXXX.json
        └─ previews/U+XXXX.svg / .png
                │
                ▼
              evaluate
```

### 训练和实验路径

```text
CASIA LMDB + CharacterGraph + 固定随机种子
        │
        ▼
inkstruct train
        │ formal / smoke checkpoint + training report
        ▼
可选 checkpoint 生成
        │ 置信度门控
        ├─ 通过：v5 残差生成
        └─ 未通过：ComponentTrajectory v4 确定性回退

用户索引 + 实验配置
        │
        ├─ budget-sweep
        ├─ ablate
        └─ blind-pack → blind-score
```

## 生成与回退机制

默认 `adaptive` 模式的选择过程可以简化为：

```text
目标部件
  │
  ├─ 有该字符的直达整组部件轨迹？ ──是──→ 使用直达原型
  │
  ├─ 有足够跨字符证据的精确上下文原型？ ──是──→ 可靠性加权迁移
  │
  ├─ 有兼容的同部件原型？ ──是──→ 保守迁移
  │
  ├─ 有部件布局或条件单笔证据？ ──是──→ 使用较低层级原型
  │
  └─ 否 ──→ 全局用户风格 + 标准中心线
```

启用神经检查点后，外层还有一次模型门控：

```text
检查点 training_status == formal
          且
平均模型置信度 >= 校准阈值
          │
      ┌───┴───┐
     是       否
     │         │
v5 生成    确定性 v4 回退
```

`--confidence-threshold 0` 可以绕过部分保护用于诊断，但不应把这种结果描述为已通过生产校准。

## 结构不变量

InkStruct 对每个生成字符强制以下约束：

- 输出笔数必须与 `CharacterGraph` 一致；
- 输出 `order` 必须从 1 开始连续递增；
- 每一笔的 `standard_stroke_id` 必须与标准结构对应；
- 坐标必须是有限值并位于 `[0,1]`；
- 压力必须位于 `[0,1]`；
- 每笔至少包含两个点，时间戳在笔内单调不减；
- 部件引用必须有效；
- 不支持的字符写入失败清单，不能替换为相似字或占位字。

复杂的一对多或多对一用户笔画映射可用于全局统计，但不会被复制成生成结果的拓扑。这保证了异常采集习惯不会改变目标字符的标准笔数。

## 数据和版本设计

### 坐标系

| 阶段 | 坐标范围 | 原点与 Y 方向 |
| --- | --- | --- |
| 原始采集样本 | 画布逻辑像素 | 左上角原点，Y 向下 |
| 对齐、档案与结构库 | 通常归一化到 `[0,1]` | 左上角原点，Y 向下 |
| 生成轨迹 | `[0,1]` | 左上角原点，Y 向下 |
| SVG/PNG 预览 | 由渲染器映射 | 保持轨迹视觉方向 |

### 版本固定

InkStruct 通过多层版本信息支持审计和复现：

- 结构数据库记录 Schema、创建时间、数据来源和上游提交；
- 样本索引记录每个源 JSON 的路径与 SHA-256；
- 档案版本由输入索引、结构和可选模型身份共同决定；
- 生成 manifest 固定 writer、profile、结构库、生成器和参数；
- 训练报告固定 Git 元数据、配置摘要、数据索引摘要和结构版本；
- 实验配置使用固定种子、固定 fold 和明确的输出目录。

### 断点续跑

生成器会持续更新 `manifest.json`。使用相同 `writer-id`、`output-root` 和 `run-id` 再次运行时，已存在的 `trajectories/U+XXXX.json` 会被视为已完成并跳过。因此取消或进程中断后可以继续运行，而不需要删除整个输出目录。

续跑不会自动证明旧文件与新参数一致。调用者应检查 manifest 中的档案版本和参数，只有确认运行身份相同才复用同一 `run-id`。

### 历史结果如何阅读

[实现与验收记录](IMPLEMENTATION_REPORT.md) 和 [v5 实现与初步结果](V5_IMPLEMENTATION_AND_PRELIMINARY_RESULTS.md) 保存了不同阶段的样本规模、档案版本、生成目录和评测指标。这些数据用于说明项目演进，不等于对任意新用户、新档案或新机器的性能保证。

当前仓库结论是：固定种子的强制 v5 生成在已记录的 DTW/SDF 指标上弱于 v4，校准安全模式会回退到 v4，因此生产默认继续使用确定性 v4 `adaptive`。

## 能力边界与已知限制

### 生成质量

- 自动几何距离不等同于人的主观观感；正式结论仍需要盲评。
- 稀有部件、特殊字形变体或上下文证据不足时会更多依赖标准中心线和全局风格。
- `full` 模式可能过度形变，主要用于消融诊断。
- 连笔、词间节奏和整行书写布局尚未作为生产目标建模。

### 数据覆盖

- 结构库包含简体、通用繁体、少量部件符号和扩展 A 字符，但不是 Unicode 全部汉字集合。
- 9,090 字有完整部件树；484 字因 IDS 或匹配不完整走整字/笔画回退。
- 字符包目前提供大陆标准简体 GB2312 与非大陆标准简体两类规划入口，不代表完整地区字形规范系统。

### 平台与资源

- 确定性生成、结构检查、采集和大多数测试可在 CPU 上运行。
- 桌面应用需要 PySide6；源码采集器还需要 `data_collection` 内核。
- v5 训练和带 `--checkpoint` 的学习模型推理需要 NVIDIA CUDA 环境；训练还需要本地 CASIA LMDB，CASIA 数据不随项目分发。
- Windows 是已验证主平台；便携采集器构建脚本包含 Windows、Conda DLL 和 PyInstaller 假设。

### 兼容与稳定性

- 项目仍处于 `0.x` 版本，Schema 已版本化但未来可能新增版本。
- 旧风格档案可以在缺少新字段时回退，但新工具输出应保留完整版本字段。
- `scripts/setup_windows.ps1` 会使用 `venv --clear` 重建 `.venv`，不适合在未备份自定义环境时直接运行。
- 生成续跑按轨迹文件是否存在判断完成状态，改变档案或参数后应使用新的 `run-id`。

## 数据隐私与许可

### 用户数据

InkStruct 的导入器不会复制或重写原始单字 JSON，只建立包含源路径和 SHA-256 的索引。用户应注意：

- 删除或移动原始 JSON 后，旧索引将无法再读取相应样本；
- `index.jsonl` 会包含本机绝对路径，分享前应检查是否泄露目录或用户名；
- `profiles/` 是从个人轨迹派生的风格数据，也应按个人数据保护；
- `outputs/` 可能表现出用户书写特征，不应默认视为匿名数据；
- 备份和删除应同时考虑原始样本、索引、档案、评估和生成目录。
