# v6.1 exp：禁止不适合直接迁移的拆分单元

基线 `c84fef5`，本轮分支 `codex/v61-no-split-yin`。规则修复已实现；目标字的穿头关系尚未修复，二者必须区分。

## 策略与范围

生产设计采用：**整字 → 完整部件 → 关键笔替换 → 作者单笔 → 明确缺口**。完整作者实例优先于拆分拼接。本轮仍为显式启用的 v6.1 实验，不切换生产默认；验证排除同字全部样本，以免整字原稿复用掩盖跨字问题。

只增加人工确认的第一条禁止拆分规则：`尹→一＋尸`。理由是尸的左撇与尹的穿头关系不同，不适合作为直接迁移的作者部件。没有新增通用穿头分类器、跨上下文禁令、形变器或风险模型。

规则版本 `author_reuse_no_split_v1`，规则 ID `yin_no_split_yi_shi_v1`。定义位于 `src/inkstruct/reuse_rules.py`，包含路径、原因、确认案例、许可边界。开关：

```python
CandidateExpansionGenerator(profile, mapping_repository, target_repository, split_rules=True)
```

`split_rules=False` 保持旧实验行为，也是构造器的默认值，便于冻结历史对照。生产 v4 入口未修改。规则没有改写上游数据库、作者轨迹、映射或档案。

## 接入已有流程

- 复用既有候选扩展器、嵌套视图、来源检查、完整轨迹输出和单笔回退，不建立第二套生成器。
- 检索视图隐藏尹下面一、尸及其后代；完整尹节点和包含它的君仍保留。原始结构描述不删除。
- 原数据库已有子节点和动态展开使用同一规则；再次展开也不能使被禁止的子单元进入检索。
- 来源库存和目标候选均检查。已有候选池、继承放置计划再次审核，最终 `emit` 对违规计划直接拒绝，不能只关闭新展开却继续输出旧“炉→群”方案。
- 检查使用经验证结构的笔画归属，而非仅比较可能变化的虚拟节点名称。
- 完整尹、完整君、户中的尸以及其他正常用途继续允许；既有作者单笔回退从完整捕获中独立检索笔型，不声称是完整尸实例。
- 既有来源内部交叉不因参考字体不同而重新拒绝。跨部件碰撞继续检查真实线段和显示笔宽。

## 尚未解决：长撇仍没有明显穿头

同尺度局部图显示：新长撇起点仍在头横下方，未明显穿头。旧方案、新方案与当前参考的第 1/4 笔均无严格中心线交叉；当前参考两笔间距约 .01922。单笔回退仍依据这份参考安排位置，因而本轮禁止错误部件后，并未自动恢复正确的起点关系。

这是具体字形核查，不是将所有交叉当作正确/错误的分类规则。规则命中、协议通过、全作者来源都不能证明字形已经正确。当前参考布局也是后续需核查的因素；本轮没有未经轮廓证据就改写它。

下一步应针对这一已确认案例核对轮廓、笔顺与参考起点，再单独验证穿头放置约束；不可通过强行拉长、弯折供体或普遍禁止跨上下文来处理。整体生产优先级中的完整尹/君来源补充仍有价值。
