# 原生项目迁移与恢复

2026-10-13，M6-02 的软件验收子项。以下验证针对 `.inkdoc`，不代表采集器安装包、真实断电、Windows 文件系统或完整离线安装已经验收。

## 使用方式

`.inkdoc` 保存 Markdown 源码、身份、选样、字形原始资源、评价和样式。公式设置、方言、图片及模板也随项目保存；复制项目文件即可迁移这些已嵌入资源。直接打开原始 Markdown 时，仍需重新提供其字形和图片资源。

源码/Python 安装版的自动恢复副本保存在启动工作目录的 `artifacts/editor_recovery/`；独立应用使用 Qt 用户数据目录下的 `InkStruct/editor_recovery`（macOS 为 `~/Library/Application Support/InkStruct/editor_recovery`）。每个会话使用独立文件名。重开同一项目或在第二个窗口编辑，会创建不同的恢复文件；同一会话后续写入检查自己上一次保存的哈希。保留已有草稿，当前没有自动清理策略。

点击“打开恢复副本…”后，源码、选样、设置和评价恢复到未保存项目。使用“保存项目”选择正式文件位置。此操作不将恢复副本自身设为正式保存目标，也不覆盖原项目。

正式更新项目前保留 `.previous.inkdoc`。已有目的文件在初次检查或临时文件同步后的再次检查中发生变化时，保存报错，保留检测到的外部版本。这个哈希检查是乐观冲突检测，最后一次检查与替换之间仍有竞态；不是跨进程锁或跨机器事务。

## 可保存的超限草稿

文档节点、嵌套、页面或路径点超限时，编辑器仍可保存完整源码、身份和有效的已有资源为 `.inkdoc` 草稿，自动恢复副本也不依赖成功的页面快照。超限状态禁用正式导出；拆分/简化后重排，未读入的外部字形可能需要重新导入。保存冲突及资源校验不被绕过，详见 [文档总量限制](DOCUMENT_LIMITS.md)。

## 校验与错误边界

- 校验 ZIP 成员数量、大小和哈希，以及原始字形与嵌入几何的对应关系；成员哈希用于损坏检测，不是数字签名。
- JSON 根类型、重复键、非有限数、过深结构、资源描述、选样版本和评价记录不合法时，报告错误。路径优化必须为布尔值，反转策略必须与优化一致；不再将字符串 `"false"` 当作开启。
- 加载失败后当前编辑窗口的源码、身份、选样、评价、设置、预览和保存位置保持不变。
- 写入先在相同目录形成临时文件，同步后替换目标；本轮故障注入覆盖同步失败、替换失败和写入中途外部修改，检查目标文件保留及临时文件清理。没有模拟真实硬件断电或验证目录项持久化。
