# Markdown 文档总量限制

2026-10-13，对应混排计划第 12.3 节。以下为本机原型的初始工程阈值，防止多个元素的独立上限在整篇输出中相乘；不是机器最大能力、RSS 硬上限或完成时间保证。普通正文和单个资源已有的限制继续适用。

## 范围和阈值

| 项目 | 当前上限 | 计数口径 |
| --- | ---: | --- |
| 源码 | 100,000 Unicode scalar | 沿用 SourceSession 原限制 |
| Markdown 块 token | 50,000 | 沿用局部块解析限制，错误类型已统一 |
| Markdown 总 token | 100,000 | 同一次解析创建的块及行内 token 总数，跨段落累计 |
| 语义及数学节点 | 50,000 | 合并统计语义树和各公式树，每个树位置均计数 |
| 合并结构深度 | 64 | 语义树与所含数学树连接后的深度；解析器本身仍有 Markdown 32 层、公式 32 层等独立限制 |
| 页面 | 200 | 正文、脚注续页、重复表头和模板复合后的页面数 |
| 页面路径点 | 2,000,000 | 整篇 paint/preview 路径点，含边框、装饰、重复内容、模板线；不把多页上限相乘 |
| 布局累计展开点 | 20,000,000 | 一次外层布局内创建的 PaintOp 点数，含嵌套脚注、模板、坐标搬移和中间步骤 |

节点审计使用迭代遍历，先于递归布局。解析初建、HTML 表格展开、脚注和公式编号处理后重新核对节点与深度；已有 AST 直接调用布局也需要检查。工作计数使用请求局部 ContextVar，嵌套布局继承同一计数，失败退出后恢复，后续请求不承接上次用量。

分页在创建下一页之前检查；正文、表格、脚注复合和固定字段的暂存路径在追加时累计。200 万点也约束合并边框前的暂存阶段，可能比最终去重后的点数更保守。最终快照再核对整篇页面与路径点，不能只检查每页或每个元素。图片像素、文件字节、资源目录读取仍由各自现有校验负责，本限制不覆盖全部内存分配或 I/O 成本。

新策略针对 Markdown 混排。旧纯文本布局和独立表格工具保留原有边界；不改变机器 SVG 的 path/M/L 格式、笔迹点、表格 160/8/3.8/0.3 mm 默认值，以及优化开启时自动允许反转的策略。

## 超限行为与草稿

超限抛出 `DocumentLimitError`，携带类别、当前计数、阈值，并提示拆分文档或简化路径。它不会生成截断的“成功”快照，不自动缩字、删内容、简化字形或放宽限制。编辑器保留源码，旧快照保持不可评价/正式导出；需解析当前源码的模板、图片设置也会显示明确错误。

在现有资源与项目数据有效时，超限文档仍可保存为 `.inkdoc` 草稿，并可写入自动恢复副本。草稿包含完整源码、身份、当前已有资源、选样及设置；不含伪造页面。若新内容所需的外部资源尚未成功读入，后续需要重新导入。损坏资源和保存冲突仍按原规则阻止覆盖，不因“超限草稿”而绕过。

上限策略及版本参与解析/布局缓存键；读取缓存后的语义树与快照仍核对当前限制。页面预览、调试预览和写字机快照适配入口再次检查，不能用历史快照绕开当前策略。命令行 render 超限返回失败码 2，未创建最终输出目录。源文件不被修改。

## 阈值依据与证据

采用已有 Apple M4 / 16 GiB 基线作为参照：真实数字 50 页约 66 万路径点，先前多快照测试 RSS 约 503 MiB。当前限制给现有样张留出余量，但不据此推断任意 200 页文档都具有相同耗时或内存。变更这些工程常量时需要同步策略版本和缓存键，并重新验证固定输入；界面不提供自动解除限制选项。

本机记录位于 `artifacts/markdown_mixed_m6_20261013/document-limits/`。回放包含原 22 个项目的 67 页及真实数字 1/10/50 页，共 25 项目、128 页；记录每项语义/数学节点、合并深度、页面、路径点、解析 token 及累计展开峰值，并比较未缓存、首次缓存、命中和冻结机器 SVG。它不替代 Windows、离线安装和真实写字机验收。

最终全量 **1152 passed、4 skipped，49.53 秒**；限额/取消/恢复专项 **41 passed**，旧解析兼容与限额专项 **28 passed**，相关 Ruff 通过。128 页冻结 SVG 全部逐字节一致。语料中单文档各项最大观测分别为节点 5994、深度 11、页面 50、路径点 726450、Markdown token 7326、累计展开 1442656；这些最大值不一定来自同一项目。

自动测试包含恰好到边界/跨越边界、已有千层 AST 在递归布局前拒绝、公式与语义节点合并计数、脚注共享累计工作量、重复模板栏位、缓存策略变更、旧快照预览/导出拒绝、CLI 无部分目录、Qt 草稿/恢复和下一次有效请求。一次回归发现旧测试要求的 `nesting` 错误标识丢失，已保留该标识并重新全量验证；失败日志仍保留，最终结果见 `full-tests-verified.log`、`replay-final.log` 与 `verification.json`。


## 标点间距（应用 0.1.29）

`inkstruct_flow_style_v4` 独立保存 `punctuation_spacing`（`capture` / `handwriting`），并保留 v3 的 `latin_spacing`。旧 v1/v2/v3 继续按采集留白读取，写回旧协议不注入新字段；显式切换到紧凑标点时使用 v4。新文档默认紧凑，中文不预留半字或整字空间；字形采用冻结的光学校正框计算宽度，保留笔迹大小、基线和校正语义。公式、代码与表格数值对齐规则不受影响。此处为排版样式版本，字体和模板协议不递增。


## 紧凑数学（应用 0.1.30）

`inkstruct_math_style_v2` 显式保存 `spacing_policy`，取值 `capture` / `handwriting`。旧 v1 不写入此字段，读取默认 capture，保留旧公式输出。新应用默认使用 v2 handwriting，旧文档和字体不自动升级；样式版本、模板版本、字体版本及应用版本独立。新策略保留公式显式空格、字号、轴线与校正参考框，不放宽缺字、笔宽、来源、几何与导出校验。
