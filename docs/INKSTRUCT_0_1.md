## 使用顺序

1. Windows解压 `InkStruct-0.1.66-Windows-x64.zip`，保留完整InkStruct目录并打开 `InkStruct.exe`，无需另装Python。工作区和个人数据保留在应用包之外；已有Windows工作区继续使用。历史macOS交付的 `InkStruct.app` 与 `~/Library/Application Support/InkStruct/workspace` 路径仅作历史参考。
2. 在“采集”页选择或新建书写者。新建填写显示名称，程序生成稳定唯一 ID；旧 user_001 可直接选择，修改名称不改样本身份。汉字使用“汉字样本”，其他字符使用“标点与扩展”。点击“创建任务”，在弹窗确认任务名称、书写者、每个字符采集份数（默认 5，范围 1–100），勾选英文正体、英文斜体、数字、运算符、希腊字母/变体、括号、标点等类别。弹窗显示总样本数；可同时采集同一英文字母的两种写法。取消不改变当前任务。已有任务保持创建时的类别与份数。
3. 生成页用下拉框选择当前采集目录中的书写者，也可填写已有外部作者 ID。样本目录默认跟随所选书写者。手选有效外部目录会保留，导入前核对作者归属。查看上次导入时间、成功导入份数和有效供体份数。通过“内置字表”“导入字表”“从文档提取汉字”或“从当前排版提取”选定目标后，点击“开始生成”。结构库全部汉字在内置字表内独立选择。首次使用或样本变化时自动导入并建档。仅缺所选方法档案时沿用有效索引建档。档案和样本有效时直接生成。准备失败时显示阶段和原因，保留上一次成功记录。默认选择 **v6.2 exp（推荐）**，可切换为 **v6.1 exp** 或 **v4 adaptive**。建档统一准备所选方法的档案，无需另建高保真副档案。应用移除神经网络生成、训练及 CUDA 检测入口。
4. 点击生成页的“制作字体…”，自动带入本批结果，并预选当前采集目录下同一书写者的扩展样本。从字体库也可先选书写者，再选本地批次或外部生成目录。在“添加标点与扩展样本”选择采集目录或 ZIP，核对批次日期、方法、完成／目标字数和状态，再勾选要入包的类别。已取消批次可使用已完成部分。本次零字时，如有可用结果，按钮显示“制作上次批次…”并标明上一批的作者、日期和完成字数。清单区分独立录制、同形共用、规则合成和未通过校验，列中为字符数／候选份数。展开查看具体字符的覆盖，从“复用与合成规则”查看依赖、逐条启用状态及本次结果。更换来源、勾选类别或改名后自动重新核对，核对期间制包按钮禁用。同形共用分全半角、英文正斜体、拉丁正体与希腊大写三组，可整组启停或逐字覆盖。启用后自动补缺，指定具体供体时才打开预览。应用设置后自动重新核对，只作用于当前制包窗口。包在暂存区通过完整验证后入库，界面选中新包并显示实际覆盖与差异。
5. 在字体库导入 `.inkfont`，选择“用于当前文档”或“设为新文档默认”。模板库可以编辑内置“普通页面”的纸张及四边边距，也可另设其他新文档默认模板。已有项目重开时读取其内嵌模板、字形与选样。左侧输入或粘贴 Markdown，右侧预览。
6. 有来源缺口时，状态栏会提示；排版页“查看问题 → 字体提示”可查看本次使用的字、参考替代笔序及原因。机器导出会要求确认未确认的缺口，可继续使用，不要求立即补采。
7. 保存为 `.inkdoc` 冻结字形、度量、候选选择、正斜体选择和确认状态。字体包项目使用文档协议 v2；旧编辑器不支持 v2，必须使用本版或更新版。普通旧资源项目继续使用 v1。
8. “导出 SVG”生成写字机页面，SVG 的子元素只有 `path`，路径指令只有 `M` / `L`；优化路径延续自动允许反转策略。采集 JSON、字体包和项目中的原始轨迹不会因此被改写。

## 字体版别与边界

用户版包含排版所需的所有点列、动态字段、度量、候选身份、来源摘要和缺口；开发者版在同一核心上增加供体、标准笔画、分组和生成记录。用户版移除开发记录，不重新生成或抽样。导出新文件不会覆盖现有发布文件。

开发者版的主机绝对路径转换为外部引用标识，采集设备元信息默认不加入；原始作者档案、结构库等仍可能是外部依赖。记录完整不等于独立可复现。字体包不是系统 TTF/OTF 字体。

正文中的英文字母选择正体；公式变量选择斜体，函数名和显式 `\mathrm` / `\text` / `\operatorname` 选择正体。缺少对应类别时允许使用已有类别并提示；不会自动倾斜轨迹。本次实际符号样本没有英文字母，因此正斜体分流使用合成测试样本验证，不能据此认为已经交付了真实英文正斜体字库。

字体读取只消费已完成字形，不拆部件、不重新生成。应用现已从真实采集样本建档并运行 v6.1 exp 修正流程，**应用默认 v6.2 exp，保留 v6.1 exp**；独立 CLI 默认没有改变。沿用排除同字供体规则，覆盖率不能解释为生产中允许整字优先复用时的覆盖率。来源完整和视觉质量分别记录，未人工检查的候选仍为未评价。

汉字采集继续遵循现有标准笔数检查。符号实录允许非标准笔数，进入排版资源不代表具有标准笔画映射或可用于部件生成；生成字体和编辑字形不会被反向当作真实采集样本导入作者档案。

## Windows 采集差异

本轮对照共享目录 `/Volumes/192.168.1.102/InkStruct/InkStruct`。外部采集内核的 Python 文件经换行规范化后与本机一致；已合并 InkStruct 符号采集包装层的实际差异：画布 50%–150% 缩放、引导线随画布同步、未保存笔迹时禁止修改画布尺寸。新增正斜体标签随任务和样本保存。共享目录及原始采集文件未改写。

## 实现入口与验证

- 集成入口：`inkstruct-app`，或 `python -m inkstruct.application`。
- 应用构建：`python packaging/build_inkstruct_app.py --output <新目录>`；输出源码摘要、依赖版本及前台应用元数据检查记录。
- 包内自检：`InkStructTool --inkstruct-check --output <新目录> --font <用户版字体> --samples <真实汉字采集目录> --writer <作者ID>`。使用离屏 Qt，模拟采集输入，实际对两种方法分别导入、建档与生成，加载完整字体并验证输入、粘贴、文档往返、SVG 输出。
- 完整字体源数据比较：`scripts/validate_font_publication.py`，逐字读取源轨迹、来源侧记录及缺口；比较每一个点的 x/y、压力、时间、笔状态、度量；另检查用户版和开发者版身份不变。
- 产物与验收数据：`artifacts/inkstruct_0_1_20261014/`。最终统计见该目录 `RELEASE_REPORT.md`。

build-v3 已完成 Finder 双击启动、原生输入/粘贴、撤销/重做和跨应用切回后的焦点验证；记录见交付目录 `native-ui-verification.json`。未验收中文输入法组合输入。模拟笔迹不能代替真实数位板和纸面写字机验收。Apple 开发者签名和公证尚未配置，当前包使用本机构建的临时签名。

## 生成流程更新版

生成页的浅绿色显示已处理比例，深绿色面积显示各阶段速度，右侧横线上方显示近期速度（字/秒）。失败的字计入已处理数量并单独列出。每次导入、建档和生成创建新批次。新增、重录或移动样本后，下次“开始生成”时自动纳入变化。全库生成可取消并保留完成部分。

v6.1 使用参考修正、完整部件和受约束的候选扩展、禁止拆分和位置变体检查、原有羊部件第六笔替换规则、作者单笔回退与明确缺口。运行依赖本次建档和随应用附带的结构资源，不依赖历史全库结果目录。历史作者特定人工冻结布局不会套用于新档案。关键笔替换没有扩展为任意部件任意笔的修复。

结果保存在工作区 `generation/outputs`。v6.1 保存方法版本、输入与代码哈希、修正与规则版本、供体、共用变换、逐笔来源和缺口；v4 保存实际引擎、固定配置和来源未知提示。字体用户版保留方法版本与来源摘要；开发者版增加详细记录。仅发布完成且协议有效的字，失败与取消清单保留在运行目录，发布前核对完成数。

Matplotlib 的几何判断是当前参考轮廓修正的必要依赖，随包保留；PyTorch、CUDA、训练依赖不随包提供；用户应用和包内工具不暴露研究 CLI 转发入口，历史 CLI 需在独立源码环境运行。来源缺口按实际使用字符汇总提示，可继续使用；协议错误不能放行。生成页不展示完整异常堆栈，详细诊断单独存入 `generation/errors`。

本轮可复现实验入口：`scripts/verify_application_generation.py`；原生成流程验收记录位于 `artifacts/inkstruct_0_1_generation_update/`；0.1.2 的字体制作流程验收位于 `artifacts/release_0_1_2/`；0.1.3 的界面与打包记录位于 `artifacts/release_0_1_3/`。新应用版本为 0.1.3，使用独立版本文件名交付，保留历史应用包。
