# Markdown 混排性能验收

2026-10-13，M6-03。固定输入、测量入口与原始观测已保存；性能结果只适用于下面明确的文档和参考机，不代表任意 Markdown 或所有真实手写资源。

后续编辑器已接入解析、资源解析、独立度量、完整布局、路由和页面 SVG 缓存，另见 [内容缓存测量](MARKDOWN_CACHE.md)。本文保留未启用这些缓存的完整重排基线，不用缓存命中成绩替换它，也不将新增内容重排误称为命中。

## 输入与测量方法

公开输入位于 `tests/fixtures/markdown_mixed/performance/`：1、10、50 页固定 A4 文档，包含标题、正文、引用、列表、数字表、分式和代码块。源文件哈希由 manifest 固定，原生项目使用确定的文档 ID 和字符锚点。每份文档分别使用内置单线数字、user_001 的 11 类/55 份真实数字与小数点样本运行，私有原生项目和轨迹保存在忽略的 `artifacts/` 中。

正文 6 mm/行高 9 mm，表格 160/8/3.8/0.3 mm，公式采用独立默认参数；没有为达到页数或速度修改产品默认值。同一源码分别生成 1、10、50 页，所有页数均由排版结果断言。

每个大小和资源组合测五次，每次新建 Python 子进程。报告 P50 和最近秩 P95；五次观测的 P95 即最大值，这是小样本描述统计，不是稳定负载的尾延迟保证。没有主动清空操作系统文件缓存。测量时不并行运行回归或其他基准任务。

- **冷排版**：新进程读取已选样、嵌入资源的项目后，首次解析加布局；模块导入、项目读取与首个快照就绪另列。
- **热重排**：沿用资源和选样，但仍完整解析、度量和分页，没有段落增量缓存。
- **局部编辑**：把首次出现的 `12.50` 首字改为 `2`，对全篇重排，确认未改实例保留身份和选样；撤销后页面几何须与原始一致。
- **阶段拆分**：分别计时解析、顶层度量、正文断行、其余分页/几何展开/校验，后者为剩余耗时，并非单独分页算法的纯耗时。表格和代码内部断行计入对应度量阶段。
- **导出**：使用正式 `export_plan`，开启优化并自动允许反转。单独记录路由及序列化/文件写入，同时测量 144 dpi PNG 的栅格生成和编码写入；不以写入成功代表机器效果。
- **内存**：记录进程 `ru_maxrss` 高水位，含导入、资源、四个快照、导出缓冲等。不是单个快照的独占内存；macOS/Linux 单位在脚本内分别换算。

各组合保留首轮完整 SVG/PNG，其余轮保留原始计时和全部 SVG 哈希，要求重复输出逐字节一致。参考机为 Apple M4、10 个逻辑 CPU、16 GiB 内存；OS、Python、Qt、布局版本及模块哈希详见每组 `environment.json`。

## 解析取消

基线中，50 页解析过程没有检查取消事件，实际工作函数的取消确认延迟为 104.9–120.9 ms。现将共享取消信号接到源映射、解析器规则、语义 token/字符生成及后处理边界。每个请求持有独立解析器，不修改全局规则；保留 Markdown 规则的 alternative chains，非取消请求的树、身份、范围与诊断必须完全一致。

本机修复后的五次实际 `build_markdown` 测量为 0.02–0.60 ms。计时从实际 `Event.set()` 到抛出取消异常，不包括 GUI 信号投递；请求由解析入口后 5 ms 定时器发起，实际启动受线程调度影响，原始请求时刻一并记录。这只是本固定样例，不是任意超长 token、HTML 表或所有输入上限的统一取消延迟保证。

补充使用最终真实数字 50 页项目运行同一探针，五次取消均成功，实际延迟 0.13–0.18 ms，证据为 `performance-validation/cancellation-user001.json`。

本节原始基线没有覆盖可见交互帧、Windows 调度或 GUI 取消确认。后续缓存实现见 [缓存与续排](MARKDOWN_CACHE.md)，Qt 取消投递补测见下节；这些结果均不能代替原生可见帧验收。原计划的候选目标仍按各自范围独立验收。

## 2026-10-14：实际 Qt 编辑取消链路

## 2026-10-14：修正测量准备开销并提前取消旧任务

继续分段测量发现，上节脚本在启动后台任务后才构造等待用的 Qt 对象和连接，构造过程也参与线程竞争。因此历史 78–127 ms 的回调延迟包含测量装置开销，不能全部归因于编辑器；历史原始数据保留，但不再用它判断产品调度性能。当前脚本先准备对象，再在已运行的事件循环里启动任务，并分别记录同步启动、定时器注册、光标设置、源码事务和实际线程身份。仅调整测量方法的五次离屏结果见 `prepared-event-loop.json`，定时回调中位约 32 ms；源码事务首次仍有 158 ms 尖峰。

产品修复为：普通内容修改与输入法正式提交一旦确认有源码事务，立即设置旧任务的取消信号，再进行 UTF-16/换行与身份映射。原有 textChanged 调度、revision 检查、选样和发布门槛保留。输入法预编辑不触发源码事务。此前旧任务一直运行到映射结束，会与界面处理竞争；同后端五次原型测量的首次事务降至约 6 ms 后才接入源码。没有加入周期 sleep、改变解析/分页算法或取消校验。
