# macOS 原生拼音输入验收

2026-10-14，M6-01 的局部实机结果。使用 macOS 27.0.1 arm64、Qt 6.9.2、Cocoa 平台及当前源码，在独立临时编辑器窗口验证系统自带拼音。系统已经启用并选中拼音，无需新增或切换输入法。没有修改产品代码。

## 实际操作

初始源码为 `12.34`，仅启用内置数字轨迹。所有按键通过桌面界面发送，没有粘贴中文，也没有构造 Qt 输入法事件。

1. 将光标移到末尾，输入 `ni`；窗口显示带下划线的组合文字，正文仍为 `12.34`。
2. 按 Escape 取消；原始文字及字符身份不变。
3. 输入 `nihao` 并按空格，实际提交一次 `你好`，正文成为 `12.34你好`。
4. 按 Command-Z 撤销，恢复 `12.34`；按 Command-Shift-Z 重做，恢复 `12.34你好`；再次撤销恢复原稿。
5. 保存验证记录并关闭临时窗口，不保存测试文档，也不写恢复副本。

## 结果与证据

捕获到 7 次非空组合文字事件和一次中文提交事件。所有未提交事件，包括取消组合输入，都保持源码和已有字符身份不变；重做后的两个中文字符仍使用首次提交分配的身份。两次撤销均恢复全部原始字符身份。最终未优化机器 SVG 与初始 SHA-256 一致：`638a12d0a8db4c302015159b1206ca48246dbd56a47062f68e5435140ac4e42d`。

界面在提交“你好”后报告两个缺字，禁用成品导出；撤销后诊断消失并恢复导出。这是该纯数字测试资源的预期行为，系统字体没有被当作手写资源用于成品。

证据目录 `artifacts/native_ime_20261014/`：

- `probe.py`：实际窗口及事件观察脚本，原输入法处理函数完整执行；F8 在窗口销毁前生成结果。
- `verification.json`：平台、脚本/产品源文件哈希、真实事件前后状态及 SVG 哈希。
- `events.json`、`states.json`：事件和状态过程记录。
- `audit.json`：额外核验取消、两次撤销及重做的字符身份和源码顺序。
- `restored.png`：恢复原稿后的窗口抓图。组合文字的原生界面截图已在本次对话中查看，未另存文件。

首次运行的实际输入流程成功，但验证脚本在窗口销毁后读取 Qt 定时器时失败，没有形成最终通过记录。`probe-first.py`、`events-first.json`、`states-first.json` 保留该次过程。修正记录时机后完整重跑，最终进程退出码 0。系统输入法曾输出 IMK/TSM 提示；本次流程仍完成，不能据此声明所有系统输入法状态均正常。

## 适用边界

本次证明当前 macOS 系统拼音、短文档末尾输入、取消、提交及键盘撤销/重做的闭环。没有覆盖所有第三方输入法、选区替换/重转换、长文档并发重排、Windows 或独立应用包的同项实操。之前的 Qt 合成事件测试继续保留，但不替代这里的原生证据。M6-01 仍未整体验收，系统缩放切换/跨屏、Windows 及设备纸面验证继续待办。
