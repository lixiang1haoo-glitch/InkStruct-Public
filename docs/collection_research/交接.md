# 字集研究第一版交接

字集组维护[推荐说明](README.md)及字集清单。Android 组使用任务包核对任务读取及实采回传，组长审核主仓库 PR 和联调结果。

## 下发录制任务

根据录入进度选择 `starter32`、`add68` 或 `total100`。已有起步 32 字时使用 `add68`，从零开始时按所需预算使用 `starter32` 或 `total100`。每个任务目录含同版 `plan.json` 和 UTF-8 BOM 编码的 `characters.csv`。分发时将两个文件放在同一 ZIP 根目录，保留文件名和原始字节。三个现成 ZIP 在队内第一版研究包的「录字清单」目录。

`plan.json` 中的目标顺序、候选顺序、文件哈希和修订号绑定本版任务。若要修改清单或份数，按[共用接口约定](../team_tasks_20261022/共用接口与验收约定.md)递增方案修订。按同一作者 ID 回传原始笔迹和采集元数据。正式留出字使用独立任务和批次，建档时隔离其全部样本。首版任务包已做本地格式和字节核对，实机读写由 Android 组联调。

## 查看和复核实验

队内第一版研究包的 `客观评测报告.pdf` 是阅读入口。`评分数据/评分汇总.csv` 按作者及预算列分数，`逐字评分.csv` 可按字查询，`同字原稿DTW.csv` 记录 300 条同字对照。图册每位作者展示 400 个目标，蓝色表示本人笔迹，橙色表示参考骨架。两份 400 字清单的用途见推荐说明。

在仓库根目录运行 `python scripts/collection_research/verify_first_release.py` 核验清单成员、任务文件哈希与预算。原始数据的复跑需取得授权样本及参考资源。按研究包 `复跑/reproduction.json` 核对资源与原稿哈希，运行同目录 `reproduce.py --help` 查看参数。复跑目标选择 `primary` 时使用完整一级表。原始轨迹、识字模型结果及评分明细随队内研究材料保管。

## PR 提交

分支为 `codex/collection-first-release`，目标为主仓库 `main`。经审查后执行 `git fetch origin main`。如果主线有新提交，先检查与该分支的合并结果，再将本地提交接到更新后的主线并复核差异、重跑任务校验。确认后推送字集分支并开启 PR，组长负责合并。

Git 跟踪字集 CSV、任务配置、说明、交接和校验脚本。原稿、档案、模型权重、逐字结果、评分文件、图册与整包按[仓库协作约定](../COLLABORATION.md)随队内交付保管。
