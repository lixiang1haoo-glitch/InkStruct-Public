# v6.3 连笔生成原型

v6.3 在 InkStruct 0.1.70 接入桌面采集和生成流程。v6.2 继续负责分笔档案、作者布局和参考回退。v6.3 增加一种保留物理笔段的作者供体，默认生成方法为 v6.3。从 0.1.76 起，桌面生成默认开启「优先使用已录同字」，使用通过整字校验的同作者分笔或连笔原稿。

## 采集与建档

连笔采集器分别显示物理笔段数和结构库标准笔数。它允许笔数不同的汉字保存，原始点序、坐标、压力和时戳继续写入现有的 `handwriting_single_v1`。它仍要求先抬笔，并保留画布边界检查。连笔入口需要明确指定隔离工作区，数据写入其中的 `capture-v63`。

建档先走已有的作者和原始样本检查。已通过 v6.2 分笔供体检查的样本继续由 v6.2 使用。其余样本进入有序轨迹对齐，比较一对一、相邻两个标准笔位共用一段实录、漏笔、多余实录以及额外抬笔等解释。对齐使用有方向的空间覆盖、首尾位置、长度和替代解释的分差。两笔共用时，每笔必须有来自自身独有轨迹的证据。仅用于计算证据的重采样点不会写入供体。

- **整字**要求标准笔位全部有可信匹配，并覆盖全部原始物理笔段。跨部件连写可随整字保留。
- **部件**要求该部件自身的笔位完整、物理笔段连续，且没有跨越部件边界的笔段。部件外存在漏笔、低置信度或多余笔段时，仍可单独收录通过的部件。档案报告把局部准入和整字准入分开。

## 生成、制包与文档

跨字迁移要求同作者、相同部件变体和位置角色，且标准笔位顺序、类型及参考对应检查通过。目标槽使用 v6.2 已生成字形中对应部件的位置和大小。分笔供体足够时，可以使用 v6.2 从作者样本得到的布局。参考替代仍带来源提醒。整个连笔部件采用一次等比缩放和平移。位置或比例不合适，或产生新的跨部件交叉关系或笔宽接触时，保留 v6.2 结果。当前每字最多迁移一个部件。

生成清单用文件摘要绑定每个字形。每段输出记录物理笔段、所覆盖的标准笔位和来源，包内按照物理笔段绘制。压力及笔段内的相对时间保留，段间时间统一重排。制包复用既有作者核对、覆盖预检、完整验证和原子入库。文档仍按原格式嵌入并冻结所选候选。

整字原稿在每字候选上限内优先保留。剩余名额可用于生成备选。制包后，自动排版优先在合格整字原稿之间选样。取消「优先使用已录同字」可运行跨字生成评估。

## 运行

下列独立诊断命令用于复现实验，只输出一份候选。桌面入口提供完整批次流程和每字多候选。命令需要锁定的结构库和参考资源，采集入口还需要已配置采集器和 PySide6。

```powershell
inkstruct v63 capture --workspace $workspace --database $database
inkstruct v63 archive --source "$workspace/capture-v63/samples/alice" --writer alice --database $database --output "$workspace/archive"
inkstruct v63 generate --archive "$workspace/archive" --database $database --reference-root $referenceRoot --text '明想' --output "$workspace/generation/outputs/v63-run"
inkstruct v63 package --run "$workspace/generation/outputs/v63-run" --writer alice --name '连笔试验' --library "$workspace/fonts"
```

`generate --same-character` 开启已核准的同字整字回放。部分批次需要在命令行显式传入 `package --accept-partial`。带符号来源制包时可传入 `--symbols`，也可在隔离工作区的现有字体库按作者选择该批次并调整覆盖。

目前重点验证两个相邻标准笔位共用一个物理笔段，以及左右、上下结构的完整顶层部件。真实自然连写、三笔及以上的连写、错序连写、作者在不同字形中的风格稳定性，以及实物笔宽导致的贴边误差仍需专门验证。
