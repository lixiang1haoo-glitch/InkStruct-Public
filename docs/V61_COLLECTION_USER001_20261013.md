本轮交付可执行的有限补采清单和真实来源审计，尚未采集新笔迹。生产默认、作者旧档案、结构数据库及旧输出不变。这里的“预计”是新采样满足现有准入条件后的来源机会，不能当作已改善的生成质量。

## 复用与准入口径

- 从 `recommend.py` 提取原有贪心边际覆盖选择器，旧规划器和实验规划器共用。旧规划器的五档阈值、计分和默认调用不变。
- 从 `exemplar_index.py` 提取原有公开参考形态兼容性计算，实验预测与实际候选过滤使用同一逻辑，门槛不放宽。这仍带有当前参考形态过滤的局限，不能解释成作者风格评分。
- 复用完整档案提取、可靠嵌套视图（需、汤）、v6.1 候选池、统一变换与生成验收；未另写映射器或生成器。
- 当前可用性必须来自真实完整实例：同作者、部件身份与变体、位置角色、父布局、笔数、可靠映射与版本一致。逐个替换当前固定布局中的部件，执行真实输出检查；候选池沿用前 16 项。
- “有安全供体”指通过该固定上下文的程序检查，包括当前 0.028 显示笔宽条件及长度比例限制，不等于人工确认风格优良，也不保证所有笔宽或多个候选同时替换都安全。

三种数量分开保存：实际输出采用的来源、固定上下文可替换的供体、未来采集的公开结构兼容机会。重复采同一字不计为两个不同供体字，不平均轨迹。

## 12 字首批清单

每字自然书写两次，分两轮完成，共 24 份训练采样。每份保留完整点、压力、时间；不临摹参考笔形，不为了通过检查强行闭合或拉直。

| 字 | 补什么、服务谁 | 为什么已有样本不够 |
| --- | --- | --- |
| 请 | 右侧青 → 情 | 没有该上下文合格实例 |
| 锤 | 右侧垂 → 睡；左侧钅 → 针 | 垂缺供体；钅当前仅银一个安全供体字，后者属于备选增强 |
| 需 | 下部而 → 儒，通过已有需的嵌套视图 | 缺可靠对应实例；不能当作“而”整字复用 |
| 俄 | 右侧我 → 饿 | 已有我来自其他上下文或独立字，不能直接算右侧供体 |
| 睛 | 左侧目 → 睡；右侧青 → 情 | 目在其他位置的样本不能替代左侧；青增加不同供体字 |
| 泪 | 右侧目 → 相 | 已有同名目不满足右侧上下文；不能与睛的左侧目混算 |
| 坐 | 重叠结构的土 → 生 | 已有土来自其他上下文；仅为条件性机会，采后须检验实际接触和放置 |
| 当 | 下部彐 → 雪 | 同名来源位置不同 |
| 扬 | 右部三笔 → 荡，通过汤的嵌套视图 | 缺对应供体；当前数据库将此三笔部件标为“昜”，不表示采八笔繁体部件 |
| 硅 | 左石 → 码、砖；右圭 → 桂 | 当前分别只有确、挂可用，增加备选，不计首次覆盖 |
| 什 | 右侧十 → 针 | 已有十的位置角色不匹配 |
| 匝 | 左包围匚 → 叵 | 缺对应供体；不能解决叵内部的口 |

本地逐字说明附有其他上下文供体数量、当前安全供体身份、对应目标笔画 ID 与公开兼容性证据。选字仅使用未采过、非评价字的 GB2312 一级字或项目常用字，3–16 笔；按缺口收益和书写成本作有限贪心选择，不声称全局最优。

若新实例全部通过映射、真实来源索引、候选检索及放置，预计为 **11 个原缺来源位置、52 笔**提供新来源机会，并使另外 **5 个位置**达到至少两个不同供体字。这不是增加 52 笔的实际测量或保证；多个部件一起放置仍可能失败。**实际新增可用采样和覆盖均为 0。**

## 提前冻结的跨字验证

在补采排序前，从未采过、3–16 笔、与回归字共享至少一个公开部件上下文的 93 个项目常用字中，按固定字符哈希次序选出：**铜、懂、使、伯、枝、便、慢、悦**。每字两次，共 16 份，仅评价。固定种子、原始索引及常用字表哈希见独立 `split.json`。

验证字不参与补采排序；验证原稿尚不存在，没有读取或使用。所有同字重复采样整组排除，开发/回归目标也从来源建档和补采候选中排除。清单冻结后才检查它们与补采清单的公开关系，没有据此重排。

现有来源在这 8 字实际采用 24/82 笔。冻结后发现：锤的钅可为铜提供备选，俄、什的亻可为使、伯、便提供备选；其余 4 字作为保护对照。**该验证组没有原无来源位置预计被这批补采首次覆盖**，因此主要检验新供体适配与不退步，不能证明上述 52 笔机会能够外推到新字。保留这个负面范围结果，不事后改换验证字。
