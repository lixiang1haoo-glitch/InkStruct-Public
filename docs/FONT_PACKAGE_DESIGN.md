# InkStruct 统一字体包设计

日期：2026-10-14。本文保留生成对接与英文字母正斜体的总体设计。**0.1 已实现首个最小适配与应用集成，尚未实现全部作者工作区和增量生成管理。** 第 2 节记录的是设计修订时的基线；不能把其中“尚无适配器”等描述理解为 0.1 交付状态。当前入口及范围见 [0.1 使用说明](INKSTRUCT_0_1.md)。生成核心和生产默认保持不变。

### 0.1 实现状态

0.1.20 将应用范围与字体另存分开：单次出现只修改文档；同一样本或同字符全部样本可选择同时写入新字体版本。批量修改清除范围内的旧单字覆盖并作为一次可撤销操作。文档仍以原字体资源和精确资产身份保存校正，不自动替换为新字体，避免双重变换；字体发布失败不修改文档，异步期间文档变化也不自动套用旧操作。正斜体默认分池，跨类别需要显式选择。持久化字段及旧规则兼容，旧全文校正不自动迁移或删除。

0.1.19 增加显式几何校正另存：原包不覆盖，改动候选分配新 ID，新包分配新 release/package ID。轨迹协议仍为 `inkfont_trajectory_v1`，逐点仿射变换仅改变 x/y，压力、时间、笔状态及来源分区保留。来源摘要增加 `geometric_corrections` 审计及严格验证的 `optical_layout_frame`（原 bounds 与 metrics），保存原字距和排版原点；原候选完整快照在核心 `correction_sources/` 成员中保留，用户版转换不删审计。字体、文档格式号与 Python 库版本独立，不机械递增。文档校正保存在 FlowStyle，来源资源与冻结选样保持原字节；不会因字体库新增版本而静默更新旧文档。

已实现 `fonts/core.py` 的不可变 ZIP 核心、`fonts/importer.py` 的 v6.1/旧目录/符号适配、字体库 GUI、用户版与开发者版转换、完整性校验、按正文/公式选择英文类别、缺口汇总提示，以及 `.inkdoc` v2 的资源与使用结果冻结。旧目录来源不充分标记 unknown；有效参考回退允许排版，协议损坏拒绝导入。四位作者的完整字体包已按源数据逐点验收，最终数量及结果以交付目录的 `RELEASE_REPORT.md` 为准。

实际 v1.0 核心文件为 `manifest.json`、`index.json`、`metrics.json`、`provenance.json`、`glyphs/<trajectory_hash>.json` 和 `license.txt`；可选开发扩展位于 `development/`。轨迹使用 `inkfont_trajectory_v1` 和固定 em 坐标，既有生成协议仍由原适配器严格校验。全局来源摘要与具体笔序缺口在 core 中保留，开发记录删减不会改变候选、度量或核心身份。包文件 SHA-256 与 manifest 内容摘要分别记录，不能混同。

导入实际生成结果时没有压缩、重采样、平滑或按单字包围盒重归一化点列；符号只按采集引导线作固定单位转换。压力、时间与几何分别参与摘要。引用型动态和合成时间不标为全字实测。应用只读取完成候选；文档还会保留当前候选池以支持继续编辑，0.1 暂未实施“仅裁剪到已使用候选”的最小文档大小优化。

作者工作区、可视化候选评价/度量校准、依赖反查与增量重生成仍是设计约定。当前实际样本不包含英文正斜体，已验证的是采集字段、分池及选择逻辑，不是实际两套英文字库的观感。详细开发记录引用外部输入，不能宣称独立复现。


## 1. 目标与核心决定

统一包装生成汉字、多份实录字符、排版度量及必要来源信息，使字体可以独立管理、交给编辑器使用、由生成层更新，并分享给另一台电脑或另一位用户。

采用扩展名 **`.inkfont`**，内部为有版本的 ZIP 容器。它是中心线手写字体资源，不是系统 TTF/OTF 字体，首版不注册到操作系统字体列表。

核心决定：

1. 一个字体对应一位书写者的一套书写风格；汉字和符号可以来自不同批次，但属于同一个经过确认的书写者身份。同一字体可包含配套的英文正体和斜体，不为两者拆成互不关联的字体。
2. 一个字符可以有任意多份候选；每字 5 份是采集任务默认数量，不是格式限制。候选允许不同笔数和写法。
3. 原始记录、用于排版的中心线和校准度量分开；不为了导入而逐字拉伸、改笔顺或丢弃单点笔画。
4. 已发布版本不可原地改写；补录、生成、校准和候选筛选产生新版本。
5. 排版字体包必须自足，打开和写字不依赖生成器、模型、原始采集目录或联网。
6. 文档保存自己的资源快照及选择结果；安装字体新版不能静默改变旧文档。
7. 作者来源不完整不是发布或排版的硬门槛：协议有效且已有完整几何的参考回退字允许使用，必须保留来源缺口并按本次实际选用字汇总警告。协议损坏不能靠确认警告放行。
8. 用户版和开发者版共用核心格式；删减开发信息不改点列、动态信息、度量或候选选择。
9. 英文字母区分正体与斜体：正文默认正体，公式变量默认斜体，函数名及显式正文/单位仍使用正体。同字的两类候选分池，先确定字形类别再稳定选样。

## 3. 三类数据的职责

| 对象 | 用途 | 核心内容 | 是否能继续生成新汉字 |
| --- | --- | --- | --- |
| 字体工作区 | 作者本地制作与修订 | 采集原稿引用、生成任务、校准草稿、评价、待发布变更 | 有可用档案与生成依赖时可以 |
| `.inkfont` 发布包 | 安装、排版、备份和分享 | 已有字形、候选集合、度量、字体身份、来源摘要 | 默认不可以；不隐含生成能力 |
| `.inkdoc` 文档 | 继续编辑某份文稿 | Markdown、排版参数、模板、用到的资源及固定选样 | 不承担字体制作或生成任务 |

### 3.1 用户版与开发者版：相同核心，两种封装内容

采用同一个 `.inkfont` 协议，manifest 用 `package_kind: user | developer` 区分；开发记录放 `extensions.development` 指向的受控数据文件。开发扩展不是排版的 required feature，普通读取器可只读核心；它仍参与包完整性校验。开发者版缺少外部原始资料时仍可排版，不能宣称一定可独立复现。

| 内容 | 用户版 | 开发者版 |
| --- | --- | --- |
| 核心字形 | 完整点列、分笔/顺序、已有压力/时间/笔状态及其来源状态、度量、稳定身份、英文字母正斜体分类、候选策略 | 与对应用户版完全一致 |
| 必要来源与评价 | recorded/generated/edited/builtin，作者来源完整性，参考回退笔的稳定笔序和缺口原因摘要，人工评价与使用警告 | 相同摘要，另保留可追查的细节 |
| 生成细节 | 保留生成路径/版本、运行模式和必要摘要，可去掉供体检索内部信息 | 标准笔画 ID、部件分组、逐笔供体及样本/笔画标识、源哈希、共同变换、关键笔替换、检索选择/排序及拒绝原因 |
| 配置和规则 | 必要生成版本及配置指纹 | 原结构库/参考修正层、档案/映射/候选池、禁止拆分/位置变体、选择/布局/回退配置、输入及代码哈希，详见第 8 节 |
| 原始资料 | 默认不带本地路径、设备信息、原始采集档案、训练配置 | 可选附带；逐项标为 included / external / unavailable，并提供内容哈希与用途；默认仍移除无必要的私人路径和设备信息 |

开发版对没有记录的证据写 unknown/unavailable，不补造日志。外部引用使用内容标识及资源角色；原机器绝对路径只留本地工作区定位表，不默认传播。包括大量日志不等于包含原始数据；包括某个 `profile.json` 也不等于包含完整代码、结构依赖与环境。

开发者版转用户版是**封装转换**：复制核心，只裁去可删开发成员及私人元数据，重建封装清单与哈希；不得执行生成、校准、轨迹处理或随机选样。保留父包内容摘要、派生关系以及全部必要缺口/警告。用户版不能反向“恢复”已删除证据，只能声明开发资料缺失。两种版型的转换合同和最小读写在 P0/P1 验证，资料自动收集和完整复现工具暂缓。

数据流：

```text
汉字采集 → 风格档案 → 生成任务 ─┐
                              ├→ 字体工作区 → 校准/评价 → 发布 .inkfont
符号采集 → 多份实录候选 ────────┘                           ↓
                                                    本地字体库
                                                         ↓
                                                编辑器 → .inkdoc → SVG
```

## 4. 包目录及身份

```text
示例手写体-1.0.0.inkfont
├── manifest.json                 # 版本、字体身份、成员哈希与入口
├── index.json                    # 字符 → 候选条目；选择策略
├── metrics.json                  # 全局参考线、逐候选度量与校准状态
├── glyphs/<trajectory-hash>.json  # 完整中心线和已有动态信息；按需读取
├── provenance.json               # 核心来源摘要：类型、缺口、动态来源、适配版本
├── license.txt                   # 提供者声明的使用/转交条件
├── preview.png                   # 可选，字样预览，不参与排版
└── development/                  # 开发者版可选扩展，不参与成品排版
    ├── records.json              # 逐笔供体、映射、变换、选择及拒绝记录
    ├── dependencies.json         # 输入/代码/规则/配置及 included/external 状态
    └── sources/<source-hash>.json # 可选附带的原始资料
```

ZIP 内只放数据，运行时不执行包内脚本、不反序列化可执行对象、不主动下载外链。除 `manifest.json` 外，所有成员必须在清单中声明并记录字节长度及 SHA-256；未声明成员和重复路径均拒绝。

字体核心身份与封装身份分开，避免删减日志造成重新抽样：

| 字段 | 语义 | 何时变化 |
| --- | --- | --- |
| `writer_uid` | 本地确认映射的书写者 UUID；公开别名另存 | 不是随导入批次变化；不同来源不能只凭 `user_001` 自动认作同一人 |
| `font_id` | 这套字体的 UUID，区分楷体、随手体等风格 | 创建新字体或独立分支时变化 |
| `release_id` | 不可变核心发布版本 UUID | 核心轨迹、度量、候选策略、必要来源或评价改变则变化；仅切换包类型不变 |
| `core_hash` | 核心成员内容及候选集合/顺序/策略的摘要 | 开发信息删减不变；核心内容改变则变化 |
| `package_id` | 该封装的 UUID | 用户版/开发者版转换、附带资料或封装元数据变化则产生新 ID |
| `content_hash` | manifest 和全部声明成员的确定性摘要 | 包类型、开发资料或核心变化则变化；ZIP 压缩参数改变不影响 |
| `archive_sha256` | ZIP 文件字节的摘要，保存在包外或传输记录中 | 重新压缩可能变化；不用于选样 |

`font_version`（如 `1.0.0`）供人理解；`format_version` 决定解析协议，两者独立。`parent_release_id` 记录核心版本沿革；封装转换用 `derived_from_package` 记录父 package_id/content_hash，不制造虚假的新生成版本。同一 release_id 对应不同 core_hash 是冲突，同一 package_id 对应不同 content_hash 也是冲突；同一 release_id 的两个版型可共存。版本升级由用户主动应用到文档，不按版本号自动替换。

`core_hash` 对规范核心描述求摘要：font_id/release_id、核心 schema 与坐标版本、index/metrics/provenance 及所有 trajectory 成员的路径与哈希、required features；排除 package_id、package_kind、开发扩展、封面和包装说明。用户版与开发版复制这些核心成员的原字节，因而 core_hash 一致。核心 provenance 必须是可分享摘要，私人细节只在 development；不能在转换时重新生成一个“无缺口”的摘要。

`candidate_id` 表示某个成品候选，导入时从持久化映射分配一次，不能每次重导入随机新建。相同候选的用户/开发版沿用 ID；几何或动态变化产生新候选并记录 parent_candidate_id。度量和来源摘要另有内容身份，修订它们产生新核心发布并由文档锁定，不能借候选 ID 相同覆盖旧版本。排版选择键使用稳定的核心版本/候选顺序/选择算法/seed/occurrence，**不使用 package_id、content_hash 或 ZIP 文件哈希作为随机种子**。

内容哈希规则：先构造不含 `content_hash` 的 manifest，其成员表含其余所有成员的 SHA-256；对 manifest 进行规范 JSON 编码后求 SHA-256。首版规范 JSON 为 UTF-8、对象键按 Unicode 码点排序、无空白、非 ASCII 原样、禁止 NaN/Infinity，manifest 只允许字符串、布尔、null 和整数。验证时拒绝重复 JSON 键，不接受隐式数字或 Unicode 归一化。另可计算整个 ZIP 的 `archive_sha256` 用于传输校验，但不作为字体内容身份。哈希证明内容一致，不证明发布者身份。

```json
  "required_features": ["centerline-em-v1", "candidate-pools-v1"],
  "index": "index.json",
  "metrics": "metrics.json",
  "provenance": "provenance.json",
  "license": "license.txt",
  "members": {
    "index.json": {"sha256": "<64位十六进制摘要>", "bytes": 123}
  },
  "content_hash": "<按上述规则计算>"
}
```

实际清单必须完整列出入口文件及引用的每个成员；不允许照抄此处不完整示例作为正式包。

## 5. 字符、候选和质量状态

首版字符键为一个合法 Unicode 标量值，保存字符及码点并相互核验。统一使用大写十六进制、至少四位的 `U+XXXX` 索引键，支持补充平面。首版不支持多码点字素或连字，但将来可通过新的 required feature 增加，不能把不支持的组合静默拆字。

不做 NFKC 或视觉相似合并：`-`、`−`、`φ`、`ϕ` 等仍是独立字符。LaTeX 命令映射由公式解析层负责，字体包不重新定义语法。

每条候选至少包含：

| 字段组 | 内容 |
| --- | --- |
| 身份 | `candidate_id`、字符、`geometry_hash`、`pressure_hash`、`time_hash`、`trajectory_hash`、`metrics_id`、`source_summary_hash` |
| 来源 | `source_kind` = recorded / generated / builtin / edited；`provenance_id` |
| 字形类别与写法 | 英文字母结构化 `letter_style`（upright / italic / unspecified），分类依据 `style_evidence`；另保留开口 4 等自由标签和实际笔画数，不限制为标准笔数 |
| 评价 | `review_status` = unreviewed / accepted / needs_review / rejected；可选评价摘要 |
| 使用策略 | `enabled`、优先级档位、等权池归属；与评价分开 |
| 能力 | `centerline` 或 `point-adaptation-required`；按几何验证，不能只信声明 |

字体工作区保存详细评价历史，发布包只带作者决定公开的当前摘要。生成器置信度另存，不转换为人工 accepted。**此前“未标记大多较好”的判断不自动把所有未标记字形变成已人工通过。**

默认允许 unreviewed 和 accepted 候选参与排版，排除 rejected；needs_review 默认不参与，可在工作区明确启用。缺少可用候选时提示缺字，不偷偷回用 rejected。旧资源迁移保留已选用资源和原评价；改变候选策略属于新发布决策，不改旧文档。

首版先按字符和所需字形类别筛选，再按显式优先级选择最高可用档位，在档位内等权抽样。例如“实录优先、生成补全”必须写成包内策略，不依赖加载顺序；同档位允许五份或更多写法。正体和斜体不能因同字符而混成一个随机池。暂不做自动质量权重，以免把估计分数当作书写效果。

### 5.1 五种状态独立记录

| 维度（拟定字段） | 值与含义 | 使用边界 |
| --- | --- | --- |
| `task_status` | completed / failed / partial / unknown；附原 runner status | 任务完成只表示产物已完成，不等于全作者或观感合格 |
| `author_source_status` | complete / partial / reference_only / unknown / not_applicable | complete 仅表示作者来源覆盖；builtin 用 not_applicable；来源不足不自动禁用 |
| `protocol_status` | valid / invalid / unchecked，附检查版本/结果 | 只有已通过适用协议验证的成品可进入正式排版；损坏、非有限值等不能“继续使用”放行 |
| `review_status` | unreviewed / accepted / needs_review / rejected | 人工观感评价，不从任务、覆盖率或自动接触指标推断 |
| `usage_policy` | enabled、优先级，以及 allow_with_warning / author_only / disabled | 默认允许来源不足但协议有效的候选；author_only 是可选严格策略，不是全局默认 |

字形有几何与有作者来源是两件事：显式缺口笔若已有参考替代，属于“来源不完整但可排版”；若笔画缺失、轨迹损坏或完全没有几何，属于“缺少可用几何/协议错误”，单独报错并要求换资源或显式修改文稿，不能用来源警告覆盖。

核心来源摘要按候选保存总笔数、作者笔序集合、参考回退笔序集合、未知来源笔序集合和缺口原因码，四者关系可校验。用户版允许去掉标准笔画 ID、供体和详细检索日志，但**保留最终笔序和稳定 stroke_ref 对应的参考位置**，可在预览上定位。开发版另保存标准 ID/部件关联。`no_admitted_author_stroke` 只说明没有通过当前准入，可能来自映射、候选桶、放置或接触拒绝；不能一概翻译为“用户没有写过，需要补录”。原因无法确定时明确写 unknown。

旧结果没有足够来源证据时，协议仍可有效，来源记 unknown、允许带警告使用；不能因日志缺失自动标 complete。相反，必需文件哈希不符、互相矛盾的来源分区或损坏清单是完整性错误，不得冒充“旧版来源未知”放行。

### 5.2 本次实际使用字的汇总警告

发布阶段允许包含参考回退/来源未知的有效字形，提供包覆盖摘要即可，不强制补采。应用到文稿时先稳定选出成品，再按实际出现位置（包括公式隐式构件）汇总：例如“本次使用的 8 个字符包含参考回退，另有 2 个字符来源记录不完整”，显示“继续使用”和“查看缺口”。这只是交互示例，不是本次实测计数。

列表按字符汇总，并可展开不同候选、笔序、缺口原因、出现次数与定位；同字若选中了不同候选，不能用其中一份完整来源掩盖另一份的缺口。未使用字符的缺口留在字体管理页，不逐字弹窗，不把整库缺口都推给文档用户。

文档冻结实际候选、source_summary_hash、状态/缺口摘要、警告规则版本及本次接受的警告集合。重开与导出保留这些结果，提供持续可查看的提示；已接受且未变化的集合不反复弹窗。加入新候选缺口或明确更换字体版本后，只汇总新增/变化项。确认警告不改 review_status 或 author_source_status，也不授权协议错误；任何重排、导出或包类型转换不得暗中换字。

### 5.3 排版资格与生成来源资格

`layout_eligibility` 与 `generation_source_eligibility` 分开。非标准笔数、特殊写法的实录成品，只要满足排版轨迹协议即可作为整字资源；它不因此拥有可靠的标准笔画映射，也不自动进入部件或作者单笔候选库。

生成来源资格需经采集身份、原始轨迹、标准映射、结构版本和对应生成路径的准入校验。当前作者单笔模块还检查 `source_trajectory_v1`、结构哈希、declared/corrected 笔序、映射置信度和完整动态字段；这些是现有路径的规则，不适用于一概拒绝排版资源。

generated/builtin/edited 候选默认 `generation_source_eligibility=ineligible`；导入字体包或人工接受观感不能升级为真实作者样本。编辑字形保持 edited 与派生链，不伪装 recorded。开发版包含的真实采集源若需重新建档，走独立原始数据导入和验证流程，不从成品字形逆推采集身份，以防生成误差循环传播。

### 5.4 英文字母正体与斜体

本节为新增设计约定，首版范围为 `A–Z`、`a–z` 共 52 个英文字母。正文默认 `upright`，公式变量默认 `italic`；属于同一字体的两套配套字形。正斜体表达使用类别，不按某个固定倾斜角判断，也不把所有手写自然倾斜都自动归成斜体。希腊字母及其他文字的字形类别暂不由此规则自动改变。

#### 数据与采集

- 字符身份仍是原 Unicode，例如两个 x 均为 U+0078；不用数学斜体 Unicode 字符替换源码，不改变复制、搜索或字符统计。
- index 按“字符 → letter_style → 候选池”组织，同一字形类别内可有多种写法与多份样本；candidate_id、轨迹、度量独立。正体与斜体各用自己的 advance、bounds 和校准信息，不共享一个估算字宽。
- `letter_style` 是用户版/开发版都必须保留的核心字段；非本节范围字符不据此分流。`style_evidence` 记录采集任务声明、人工确认或未知，不用作者来源完整性或自动质量分数代替分类。
- 后续采集任务增加“英文正体”“英文斜体”，任务键包含 `(character, letter_style)`，保存时把所选类别写入每份样本；每字符每类别默认 5 份，完整采集两套为 520 份。数量不是格式硬限制，允许只先采其中一套或部分字母。
- 旧样本仅有自由备注，没有可靠结构化分类时标 `unspecified`。备注可供人工批量分类参考，不凭“手写看起来有点斜”或不确定文本猜测分类。分类修改保留原始样本字节，在工作区形成新的 index 元数据和核心发布；不重采样或改点。
- 用户/开发版转换保持分类、分类依据和候选池顺序不变。单纯修正分类不改 candidate_id/trajectory_hash，但改变 `style_key`（分类记录内容摘要）、index 及 core_hash；已有文档仍保留旧快照。

#### 正文与公式的使用规则

| 位置/语义 | 默认选择 | 规则 |
| --- | --- | --- |
| 正文、标题、列表、普通表格中的英文字母 | 正体 upright | 表格单元格内的公式仍按公式规则，不以整个块强制正体 |
| 行内或独立公式中的英文变量，包括变量上下标 | 斜体 italic | 大小写一致适用；行内/独立只影响布局，不改变此默认 |
| `\sin`、`\cos`、`\log`、`\lim` 等已识别函数/算子名 | 正体 upright | 在词法/语法节点层判定，不能对所有“位于公式内”的字母一律斜体 |
| `\operatorname{...}`、`\mathrm{...}` 中的英文字母 | 正体 upright | 显式样式在组内向下传递；说明性下标、单位可用 `\mathrm{...}` 明确表达 |
| `\text{...}` 中的英文字母 | 正体 upright | 使用正文语义；不继承外部公式变量的斜体默认 |
| 公式中的数字、小数点、括号及其他符号 | 保持各自既有策略 | 不因为相邻变量为斜体而跟随斜体 |

例如源码 `\sin x + x_{\mathrm{max}} + 12\,\mathrm{mm}` 中，sin、max、mm 使用正体，两个变量 x 使用斜体；12 的字形策略不变。直接键入未带命令的 `sin` 仍按普通变量字母处理，不通过字符串搜索擅自变成函数名。裸写 e、i、d 不自动猜成常数或微分符号，作者需要正体时显式指定。

规则优先级为“语法语义/显式组样式 → 文档对应角色的默认设置 → 精确类别候选池”。嵌套显式样式只作用于其范围；用户可在文档设置中改正文英文和公式变量的默认类别，不修改字体包内容。Markdown 强调或其他字形命令需单独定义语义，不能在本轮悄悄改变现有行为；显式 `\mathit{...}` 可作为后续受控语法扩展，当前未支持，不把它列为已可用命令。

#### 缺少某一类别时

正斜体缺口独立于“缺少几何”和“作者来源缺口”。例如有正体 x、没有斜体 x，显示“公式需要斜体 x，当前仅有正体”，不声称字符 x 完全不存在。

默认先只查请求类别；无匹配时按本次实际使用字汇总类别缺口，提供“继续使用现有字形”与查看详情。用户选择继续后，从 `unspecified` 池、再从另一明确类别池按固定顺序选取协议有效且允许使用的候选；显示实际使用类别，既不改标签也不宣称已得到斜体。没有任何有效候选仍按缺字处理。用户可以选择保持严格类别而暂不导出，不强制立即补采。

不自动剪切正体坐标来伪造斜体，不从系统字体临时替代。以后如增加显式变形工具，它应产生 edited 派生候选并保留原轨迹，不属于本轮正斜体选择功能。

#### 选择、冻结与兼容

排版请求新增 `requested_letter_style` 与 `text_role`，候选返回 `resolved_letter_style`、style_key、candidate_id 及类别回退原因。先按类别筛选，再执行已有稳定选样原则；选择版本和缓存键必须包含请求类别、角色策略版本及分类索引内容，不能命中仅按字符建立的旧缓存。

文档冻结请求类别、实际类别、style_key、成品候选和接受的类别警告。重开/导出、调整字号或切换用户/开发包不能重抽；补入斜体新版后也不自动替换旧文档中已确认使用的正体。只有用户主动修改样式/字体版本时才重新解析受影响位置，并作为可撤销文档编辑。正斜体警告与作者来源警告可共用汇总面板，但原因和接受记录分开。

旧文档已有选择优先保持其实际字形，迁移时用 `legacy-preserved` 标识未分类请求，不为套新默认静默换字；新建文档采用本节规则。声明字形分池的字体核心增加 `latin-style-pools-v1` required feature，旧读取器不能忽略它并把两池混抽。

#### 当前实现与新增接口边界

当前 [采集记录](../src/inkstruct/symbol_capture.py) 只有 `variant.note` 等备注，[资源选择器](../src/inkstruct/assets/resolver.py) 按字符建池并选样，尚无结构化正斜体路由。[公式解析器](../src/inkstruct/math/parser.py) 已识别函数、`\mathrm`、`\text` 和 `\operatorname`，但 [手写排版](../src/inkstruct/math/handwritten.py) 的字符资源请求未携带上述字形类别；解析命令不等于已经切换了字体。

需要新增采集类别元数据、旧样本分类适配、核心分池、公式/正文样式上下文传递、类别缺口与选择冻结。本轮只确定设计；不改变已保存样本、现有公式渲染或设置界面中用于标注参数的正体示意字体。

## 6. 坐标、校准与公式构件

### 6.1 保持现有 em 契约

排版几何统一为 em 单位、x 向右、y 向下；首版规范参考基线为 `y = 0.88`，与当前运行时一致。允许合法下伸、负左侧承和高于参考框的笔迹，不要求所有点落在 `[0, 1]` 中。

迁移时：生成轨迹现有单位坐标保持原值；符号按固定采集 guides 转为 em：`x = (raw_x - origin_x) / em_px`，`y = 0.88 + (raw_y - baseline_y) / em_px`。这是有版本的采集坐标适配，不是字形优化。不得按每份字的包围盒分别归一化，也不得在新增样本后重新缩放整个库。原像素坐标与适配参数可保存在开发资料中；排版核心的往返一致性从首次明确适配后的 em 数据起算，不宣称浮点逆变换能恢复源字节。

`glyphs/` 的规范轨迹记录字符、坐标协议、按书写顺序排列的 strokes 和 points；点有 x/y，可选 t_ms/pressure/pen_state。有值就完整保留，没有采集的字段保持缺省，不能用 0、常量压力或均匀时间悄悄填充。分笔边界为核心数据，即使 pen_state 缺省也不丢失。

### 6.2 明确的协议适配层（待新增）

| 输入 | 原协议校验 | 适配到字体核心 |
| --- | --- | --- |
| 旧生成 `personal_trajectory_v1`、v6.1 的 `payload.glyph` | 保持当前生成协议：单位框（按原验证器容差）、完整压力/整数时间/笔状态、顺序和有限值；v6.1 另核对配套来源记录 | 点列和动态原值复制，生成来源摘要另适配；不重新调用生成器 |
| 符号实录 | 原始 guides、坐标和已有动态字段按采集协议验证 | 固定 guide → em 变换一次，动态不重采样；记录 adapter 版本与输入 hash |
| 新字体核心轨迹 | 独立 `inkfont_trajectory_v1` 校验器：允许声明范围内的 em 超框及缺省动态，但保持有限值、非空笔画、点数/资源预算、已有压力范围与时间语义检查 | 直接读取，不能伪装成更宽松的 `personal_trajectory_v1` 再送旧加载器 |

实现入口为源格式专用 adapter → 不可变核心轨迹 → 只读排版视图。**不整体放宽 `adapt_glyph`、GeneratedGlyph 或 v6.1 invariants**。一个声明旧生成协议却越界或缺少必需动态字段的文件，仍按旧协议判无效，不能改 schema 标签绕过；合法超框的新字体/实录资源由独立协议处理。

导入、发布及用户/开发版转换均禁止轨迹简化、几何压缩、平滑、插点、删点、裁边、重排笔画、重建时间或按单字包围盒归一化。ZIP/gzip 无损容器压缩可以使用。重复坐标和短收笔仍保存；单点笔画按能力标志处理。当前项目加载器存在 4096 点资源限制，需为新核心读写路径单独测量并制定预算，不能为了塞进旧限制而压缩 v6.1 完整点列。

### 6.3 动态来源与内容哈希

动态来源按笔、按通道记录，必要时用点区间细分：

| 状态 | 含义 |
| --- | --- |
| measured | 当前真实采集记录中直接测得；有对应采集依据 |
| inherited / inherited_retimed | 压力等从供体继承；时间继承笔内间隔但重排了全字时序，记录相应规则 |
| synthesized | 参考或算法合成，记录算法版本；不能写成作者实测 |
| absent / unknown | absent 是字段不存在；unknown 是有数值但缺少可靠来源证据，两者不等价 |

当前 `assemble` 以每笔首时刻为零点取相对时间并 round，按最终笔序累计，相邻笔间加 60 ms，并重建 down/up/end。适配器原样保留**已经输出**的 t_ms/pressure/pen_state，作者笔时间标 inherited_retimed，压力按证据标 inherited；参考笔依据已知生成路径标 synthesized，否则 unknown。完整作者来源也不意味着整字时间 measured。动态来源说明留在用户版，逐笔供体详情可删。

已核查的 [FullReferenceGenerator](../src/inkstruct/v6_exp.py) 将参考压力设为 0.5，时长按路径长度生成并设最短 80 ms；这类数值必须保留，但属于合成动态，不能因字段齐全就标 measured。pen_state 经组装重建的事实也记录为 synthesized；不反向推断成原始数位笔事件。

采用带版本和用途标记的内容摘要，防止同形不同动态误去重：

| 摘要 | 必须包含 | 不包含 |
| --- | --- | --- |
| `geometry_hash` | 坐标协议、完整 x/y 数列、点序、笔序与分笔边界 | 压力、时间、供体日志 |
| `pressure_hash` | 与点对应的存在掩码、原压力数值、压力来源状态 | x/y、时间 |
| `time_hash` | 存在掩码、原 t_ms、时间单位/作用域、时间来源及重排规则 | x/y、压力 |
| `trajectory_hash` | 字符/码点、稳定 stroke_ref、上述三项、pen_state 数列/存在掩码/来源、核心轨迹 schema | 度量、可删开发记录 |
| `metrics_id` | 度量、参考线、校准版本/状态 | 点列 |
| `source_summary_hash` | 来源类别、作者完整性、逐笔作者/参考/未知分区、缺口原因和必要警告 | 供体检索详细日志 |

点序与掩码长度必须对应几何，动态摘要即使不存在也有显式 absent 身份。资源存储可按 geometry_hash 共享几何，但候选不能只凭它去重；trajectory_hash 不同必须保留。即使所有轨迹数值相同，来源/评价不同也不能自动合并候选身份。幂等导入以来源运行/候选身份和完整数据摘要核对，而不是仅比较形状。

P0 冻结跨平台规范编码和测试向量：核心数值保持输入解码后的精度，不做小数位截断或容差哈希；浮点按 IEEE-754 binary64 有序字节、整数按带类型的精确整数编码，字段/数组长度和缺省状态明确编码。JSON 负责可读存储，文件 SHA-256 校验实际字节，语义 hash 使用独立版本化编码；元数据排序或 ZIP 重压缩不能改变轨迹语义 hash。往返要求每笔每点的坐标、动态存在性和值及度量精确一致，不只比较 SVG 外形。

### 6.4 度量独立于原始笔迹

`metrics.json` 声明全局参考基线、上伸/下伸、大小写字高和数学轴；数学轴为相对基线向上的距离，不与 y 向下的点坐标混用。逐候选记录 advance、ascent、descent、真实中心线 bounds 及可选锚点。候选的参考 baseline 固定为 0.88；公式或文字排版再放置它。

bounds 根据规范几何重新计算核验，**不含笔宽**。advance 是排版前进量，不强制等于墨迹宽度；可存在左右伸出。笔宽以当前文档毫米值在排版时扩张边界，用于自动避让。字体包不固化用户的字号、行距、上下标比例或写字机笔宽。

校准状态为 `guide_based_unreviewed` / `manual_reviewed`，附校准算法版本和内容摘要。只改 advance 等度量不改轨迹身份，但改变 metrics_id 和核心发布。需要改变轨迹位置或比例时属于明确的编辑操作，产生 edited 候选及派生链，不是导入/发布时的隐式校准。生成器内部对部件/单笔的布局已经固化在成品点列中，排版层不得借校准再做一次。

### 6.5 公式能力提示

字体包可声明特定候选的构件用途及锚点，例如分数线采用减号、根号延伸连接点、括号允许缩放的方向。仅采用有版本的受控字段，算法由应用内置；字体不能提供执行代码。

首版目标是支持普通字符和现有录制构件流程，未校准的锚点不能标为已就绪。根号分段延伸、减号拉长、括号缩放属于显式公式构件排版，不是汉字供体生成；字体记录原始资源和能力，文档决定是否采用，派生场景几何不写回字体轨迹。可选构件缺失时报告能力缺口，是否选择几何构件由文档设置决定。

## 7. 字体管理与分享界面

在现有“设置 → 字形”中提供当前字体卡片和“管理字体…”入口，不再在主工具栏增加一排按钮。

字体管理窗分为：

- 左侧字体列表：名称、书写者别名、风格、已安装版本。
- 右侧概览：字样、汉字/数字/英文/希腊字母/符号覆盖、候选数量、校准状态、缺口；英文按“正体 52 字母”“斜体 52 字母”“未分类”分别统计，不能只显示合并后的 52 字。
- “字符与样本”：按字符查看候选、来源、评价与写法；工作区可排除或更换候选。
- “版本与来源”：版本变化、采集/生成批次摘要、旧版保留及来源说明。
- 常用操作：导入、用于当前文档、导出分享；创建/修订字体放在作者工作区入口。

覆盖率分开报告“存在几何”“协议有效”“作者来源完整”“含参考回退”“来源未知”“人工已审阅”“构件就绪”，不以 ZIP 文件数或任务 complete 数表示完成度。生成覆盖率必须同时显示生产/跨字验证模式及同字排除规则。首版导入 `.inkfont`，同时保留旧生成目录和符号 ZIP 入口，并可引导转为字体工作区。

分享默认仅包含规范字形、度量、公开别名、必要来源摘要和提供者填写的使用说明。源 JSON、设备信息、绝对路径、训练样本及风格档案不默认附带；规范几何本身仍包含个人笔迹，不称为匿名化。保留必要的生成/修改来源标记，不把生成字形伪装成实录。

导出前显示实际内容和大小，可选整个字体或指定字符子集。子集是独立发布，记录 parent、scope 和真实覆盖，不冒充原包完整版本。原候选 ID 在内容未变时保留。分享仅生成本地文件；发送、上传和公开发布是另一步操作。

## 8. 采集与生成层对接

### 8.1 职责边界

生成器选择真实供体、执行完整部件共享变换/已支持的关键笔替换/作者单笔回退，形成完整成品。字体工作区导入并保存**已经生成完成**的候选；字体包加载器只验证、解码和适配；排版层只在成品候选间稳定选择，并按字号、基线和页面位置放置。

读取字体包时不得重拆部件、修改单笔、再次拟合供体、改变生成内部布局，或因缺口偷偷调用另一条生成路径。作者来源层到“明确缺口”结束后，应用可接受产物中已保存的参考替代几何，并明确警告；这不把参考变成作者来源，也不改变严格 `require_author_only` 的语义。若结果没有该笔几何，读取器不能自行从参考库补上。

多候选是已经存在并有独立身份的多份成品，不等于多次重复运行。当前没有验证不同 seed 能给出自然且合格的 v6.1 字形变化，不写成已有能力，不通过改 seed 批量制造“5 份”。本轮接入优先每字一个冻结生成候选，加上真实存在的录制候选；新候选选择算法、自然变化生成和通用关键笔替换不在范围内。

### 8.2 制作服务

制作入口共用 `FontWorkspace` 服务，GUI 和后续 CLI 使用同一组读写与验证逻辑。下述名称是拟定接口，不是现有命令：

| 接口 | 输入 | 输出与保证 |
| --- | --- | --- |
| `import_recordings` | 符号 ZIP 或采集目录、作者映射 | 成品排版候选及来源资格报告；不自动用于生成建档，源文件不改 |
| `import_generation` | 冻结 run/显式字子集、格式 adapter、writer 映射 | 联合读取成品轨迹、逐字状态、来源和缺口；协议有效的参考回退可导入，不把失败目标记成已覆盖 |
| `set_calibration` | 字体/候选度量草稿 | 新校准记录及影响预览；不改已发布版本 |
| `set_candidate_policy` | 可用状态、来源优先级、标签筛选 | 可审查的候选池变更 |
| `publish_font` | 工作区快照、名称、版本、package_kind、分享选项 | 按协议/完整性校验原子发布；不以作者来源完整作为硬门槛，保留缺口警告 |
| `convert_package` | 开发版、用户版裁减策略 | 原样复制核心，保持候选及 core_hash，新增封装身份与派生记录，不重新抽样 |
| `inspect_font` | 包路径 | 覆盖、度量、来源、完整性与兼容性诊断 |

生成任务先在其原有 run 目录完成，发布过程读取不可变快照，不把仍写入的目录直接作为“字体”。允许从部分失败的 run 显式选择已经完整保存并通过校验的字子集；记录排除项和范围，不宣称整批完成。重复导入保持幂等，已完整保存的结果不重生成。重试用 run 身份与完整候选内容哈希去重，不能用字符名或单独 geometry_hash 去重。

### 8.3 最小生成结果 adapter：必须在 P0/P1 接入

按已识别的格式配置选择 adapter，不把所有文件夹都当作旧 `trajectories/`，不从 SVG、文件名或 generator 字符串猜测来源完整性。

| 结果类型 | 联合读取内容 | 适配处理 |
| --- | --- | --- |
| 旧生成目录 | `trajectories/U+XXXX.json`，如有 run manifest/已有明确来源字段则一并读取 | 原协议验证；没有证据的笔标 unknown；完整几何可带来源未知警告使用 |
| 旧 v6.1 全库 | `protocol.json`、`<writer>/<HEX>.json`、同名 `.json.gz` | `glyph` 配合 component placement 列表 provenance、checks、source/reference 统计、baseline_selection/expansion；按 placement indices 映射作者笔，能证明的参考笔显式标记，证据不足记 unknown |
| 当前修正全库 | 相同容器位置；payload 有 `glyph/provenance/stroke_sources/logs/fallback/rule_log/checks/missing/author_only_ready/source_profile_sha256` | provenance 为逐笔映射，不能套用旧版 placement 列表；联合核验 stroke_sources 与 missing，明确区分参考替代和作者笔 |

当前逐字 `.json` 有 `status/files/warnings/source_strokes/reference_strokes/source_kinds/stroke_sources/missing/checks/author_only_ready/same_character_reuse`。`status=warning` 通常表示产物已生成但有来源或几何审查提示，适配成 task_status=completed 加独立警告，不能一律当 failed；`status=complete` 也不代表人工 accepted。`failed` 单独记录失败及排除原因，不以残留文件猜测成功。

导入步骤：

1. 冻结所选文件和 protocol 字节/hash，记录源格式与 adapter 版本；验证逐字 `files` 中声明的产物哈希。gzip 以有上限的流式方式解压，限制压缩/展开尺寸、点数和嵌套，不用无限制整包解压。
2. 检查 writer、字符/码点、标准 ID/最终笔序、几何动态协议及输入记录的一致性。来源序号从当前 provenance 的零基索引映射到最终一基 order，明确保存映射，不能混用 `s2` 与数组下标 2。
3. 逐笔交叉核对 provenance、stroke_sources、missing 与实际 glyph。`explicit_gap` 且 glyph 中该笔存在有效参考点 → reference_fallback；缺几何则单列不可排版。作者/参考/未知分区应完整互斥，author_only_ready 和计数只作核对，不是唯一依据。
4. 保留原 checks，包括 protocol/source_integrity、退化、跨部件交叉及多笔宽接触提示。重新验证通用轨迹协议；源保真若需要未包含的作者档案，区分“原运行报告通过”和“本次未重验”。记录 evidence_scope，不把摘要报告等同于独立验证。明确的完整性矛盾不能警告放行。
5. 对已识别旧格式缺少的来源字段保留 unknown，并说明证据边界；对声明完整的新格式缺失必需成员则报损坏，不静默降格成 legacy。不同 schema/容器通过版本化适配，不试运行生成器来补日志。
6. 产生完整核心轨迹、必要来源摘要与开发记录引用，冻结对应候选身份；读入后不平滑、压缩、归一化、重排时间或使用 seed 重新选择。

当前缺口 `reason=no admitted author stroke` 及 `rejections` 记录的是当前选择约束下的结果。用户版映射为稳定原因码及可理解摘要，详细计数留开发版，不能从“拒绝”推断作者数据一定不存在。参考几何仍在核心轨迹中，警告不可因删日志而消失。

### 8.4 生成配置和版本追踪

开发扩展必须分角色保存依赖，不能只写一个笼统的 structure_version 或 profile_version：

| 依赖角色 | 要保存的版本、配置和证据 | 当前可读取位置 / 待补内容 |
| --- | --- | --- |
| 原结构库/映射库 | 内容 hash、结构标识、笔画 ID 体系 | 当前 `DB`、protocol.inputs 与档案 build_identity 的结构 hash；不能混成修正后的 target |
| 参考修正层/目标参考 | 修正文件 hash、应用顺序、坐标 frame 版本/变换、参考生成策略 | 当前 `CORRECTIONS`、CorrectedStructureRepository、glyph.canvas_fit/已有记录；每字依赖索引待适配 |
| 作者档案/映射 | 档案 hash、trajectory schema、建档身份、映射版本/门槛、源样本 hash | source_profile_sha256、profile.build_identity、逐笔来源；外部档案不在包内则标 external |
| 候选池 | 池快照/构造代码与配置 hash、成员/结构签名、候选过滤规则 | 当前 provenance/选择日志和冻结档案；无独立 pool_id 时记录可得构造依据，不能虚构完整池快照 |
| 禁止拆分/位置变体 | 各自版本、规则数据/hash、开关、适用范围 | `author_reuse_no_split_v1`、`positional_key_strokes_v1`；protocol.rule_version/rules 与源代码快照。并非所有版本都在顶层 protocol 独立成字段 |
| 候选选择/内部布局 | policy 名、参数、检索上限、共同变换、是否启用选择/布局、轴比约束 | v61_exp.POLICY/PARAMETERS、ExpansionPolicy/G_axes、MAX_AXIS_RATIO，及实际计划/日志；记录实际运行配置而非当前代码默认 |
| 关键笔替换 | 已审查计划 hash、适用笔位/来源、保留变换、替换原因、拒绝记录 | logs.reviewed_plan、logs.hybrid/repair、author_hybrid_retained/key；当前限已有计划，不写成通用能力 |
| 作者单笔回退 | 映射阈值、笔型桶版本、32 候选限制、端点/长度/边界/接触规则 | PARAMETERS、fallback.trials 和代码 hash；含批量检索版本，不能只记录最终供体 |
| 代码与输入 | 实际脚本/模块内容 hash、提交、输入 hash、已有计划/对照产物 hash | protocol.code/inputs/baseline_commit；工作区 HEAD 不能替代生成时快照 |
| 运行与验证口径 | production / cross_character_review / unknown、目标集合、同字排除范围、whole-character 策略、seed 的存在性 | 当前 protocol.same_character_sources_excluded=true、whole_character_priority 与逐字 same_character_reuse=false；seed 未记录则 unknown/not_applicable |

用户版保留生成路径/版本、配置指纹、运行模式和同字排除摘要、逐字必要来源状态；详细配置、供体、日志和本地定位信息可不带。统计必须分母明确（字符/笔画/作者/目标集合），不能将跨字审查覆盖率挪作完整原稿优先生产覆盖率，或以来源完整推断观感合格。

### 8.5 受影响字定位（设计约定，尚无完整自动调度）

工作区维护 candidate → 所用供体/样本/笔画/映射、参考节点/修正层、规则家族、检索池/笔型桶、生成配置版本的依赖记录，并建立反向索引。开发包可携带该索引及其证据范围；用户包不必带检索细节。

补录影响的不仅是已选供体：新样本可能进入此前没有通过候选的桶，也可能替代现有候选。因此还要记录被查询的候选池/结构签名、目标笔型和未满足需求，不能只对已使用 donor 建索引。规则修正则按相关部件/位置变体/禁止拆分节点定位；度量变更只使排版缓存失效，不要求重新生成。

先给出受影响字清单与理由，再由工作区明确启动这些字的新 run，产生新候选/发布；包读取器不自动重跑。对旧记录无可靠依赖的范围标 unknown，保守扩大到相关作者/池/规则范围，必要时全库，不能宣称已能精确增量生成。当前快照和日志可作基础，但完整反向索引及增量调度是后续工作，不在本轮实现。

一位作者的多个旧 writer_id 可经用户确认映射为同一 `writer_uid`；同名 writer_id 来自未知外部包时保持隔离。导入另一个人的字体并不会自动并入自己的字体。首版一个文档选择一个主字体；多字体回退链另行扩展，不隐式拼混作者。

## 9. 编辑器及项目兼容

新增 `FontPackageProvider`，向排版层提供与当前 `ResolvedGlyph` 相容的只读视图。读包先验证 manifest/index/metrics，再按实际字符读取并验证几何；安装完整性检查以流式方式核验所有成员，避免先把全库点对象解码进内存。

当前 `ResolvedGlyph.strokes` 只用于 x/y 排版，动态保留在 original_json 中。新增核心资源层必须另外持有完整 trajectory/dynamics/source_summary，提供 x/y 只读视图给现有布局；不能经过 x/y 视图后反向导出字体而丢压力和时间。项目新版本也需读取新的核心 schema，不能只增加 provider 标签而继续依赖旧源 JSON 分支。

新选择记录至少锁定 `font_id`、`release_id`、`core_hash`、`candidate_id`、`trajectory_hash`、`metrics_id`、`source_summary_hash`、`selection_version` 和 occurrence 身份。package_id/content_hash 只作导入来源记录，用户/开发版转换不改变选样。旧记录通过显式适配保存原 asset/sample/metrics 身份，不能因新身份模型重新抽样。

英文字母还按第 5.4 节锁定 requested/resolved_letter_style、style_key、角色策略版本和类别回退；同字符的正斜体在依赖扫描、缺口检测和快照中分别处理，实际使用的另一类别回退候选也必须嵌入。

文档快照采用以下策略：

1. 嵌入文档涉及字符的可用候选池及所有已选候选，包括公式隐式用到的减号、根号、括号等构件。
2. 某个已选候选后来被排除，仍保存在该文档快照中；缺失时报告，不自行换字。
3. 按相同字体版本和候选集恢复；新出现位置按冻结策略选样，重排与导出不重新抽签。
4. 可选“附带完整字体”便于接收者增写任何已覆盖字符，导出前展示体积差别。
5. 只嵌入字符子集时，离线增写未包含字符会提示安装对应字体或显式选择其他字体；不依赖作者电脑路径。
6. 冻结实际所用候选的作者来源状态、参考笔序/缺口、协议与人工评价状态，以及第 5.2 节的警告接受记录；缺日志不等于缺口消失。重开、重新排版和导出不暗中换用来源更完整的另一候选。

现有 `.inkdoc` 读者严格检查资源 schema，不能简单添加新 provider 字段后沿用旧版本号。新增项目版本与显式迁移读取器，旧项目继续按旧规则读取；旧程序打不开新项目时给出明确版本提示。当前旧项目默认嵌入整个池的行为维持到新读写器实现并验收，不提前宣称已经支持子集快照。

字体更新对比显示新增/删除字符、候选与度量变化；“应用新版本”属于可撤销的文档编辑，预览影响后才更新选择记录。卸载全局字体不会破坏已有文档快照。

## 10. 库存储、校验和兼容规则

本地字体库位于平台应用数据目录（使用平台标准路径 API，不写死作者目录）。可采用 `fonts/<font_id>/<release_id>/` 存发布包及派生索引。字体草稿放独立 workspaces，缓存可删除并重建，不能充当唯一源数据。

导入先校验到临时位置，再原子登记。相同内容重复导入显示“已安装”；同名不同 font_id 并列显示；同 release_id 不同 core_hash 拒绝并报告冲突。同核心的用户/开发版按 package_id 区分，可共用只读核心缓存，但不得覆盖另一个封装。跨机器安装不依赖原目录结构。

首版兼容规则：主版本不支持则拒绝；同主版本新次版本仅在所有 `required_features` 支持时允许读取；未知字段只允许进入明确的 extensions 区域，未知 required feature 不猜测降级。功能缺失与包损坏分别报告。

包读取需要拒绝绝对路径、`..`、反斜杠歧义、符号链接、加密成员、重复/大小写冲突路径及引用环；禁止 NaN/Infinity 和非合法 Unicode 字符。限制成员数、单成员大小、总展开大小和总点数，实际流式读取时再核验，不能仅信 ZIP 头。初始资源预算在第一阶段用实际全库包测量后冻结；目标至少容纳当前汉字全库加多份符号，不能照抄旧符号 ZIP 的 5,000 文件限制。

可安装、可排版与可机器导出分别判断。单点笔画应保留并标注适配需求，不能为通过包验证直接删掉；导出器按现有规则处理或阻止输出。字体包不改变 SVG 仅 path 且仅 M/L 的最终出口约束。

## 11. 实施顺序和验收

### P0：冻结数据合同与最小生成适配基线

### P1：核心读写、两种包转换与最小使用闭环

- 实现 adapter、只读 provider、原子发布、inspect、developer → user 转换；旧目录/ZIP 不覆盖，生产默认不动。

- 验收：矩阵全部通过，重复导入幂等；缺口字可经警告继续，损坏字不能；转换不重新抽样，故障不破坏旧包。

### P2：编辑器统一接入

- 把 P1 最小闭环接入正式编辑界面：字体选择、版本锁定、项目新旧版本读取、缺口汇总与定位；内置数字仍为显式回退来源。

- 上线概览、覆盖、候选检查、版本差异和完整/子集分享。

- 验收：分享内容清单正确，规范几何能独立加载；子集不带无关原始记录；移到另一目录或另一台电脑后引用仍完整。

### P4：制作流程联动（不是最小生成导入的起点）

- 验收：补录、重新生成、校准各自只改变预期内容；跨平台路径、安装和真实采集另做 Windows/macOS 验收，不能由离屏测试代替。

## 0.1.11：采集数学轴核心元数据
