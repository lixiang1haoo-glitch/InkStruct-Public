# v6.1 exp 全库参考回退审查

本轮核查 `ac5b085` 交付的四作者全库结果，不改生产、档案、参考或旧输出。目的在于解释 34.3% 作者笔画覆盖，区分真实来源缺口、映射证据不足、候选/调度范围遗漏和实际几何拒绝。

## 总体核算

38,296 份字形共 450,468 笔；作者实例 154,570 笔，参考回退 295,898 笔。以下为最终回退笔画的互斥首障碍分类，不是候选尝试次数，也不能把全部门槛命中称为误拒。

|---|---:|
| 当前登记视图中没有同名完整来源 | 173,580 |
| 已有可靠完整来源，角色/父结构上下文不在候选范围 | 58,965 |
| 实际放置未通过当前几何/协议检查 | 23,156 |

“没有同名完整来源”的结论只针对现有档案的已登记结构视图（包括根、父节点、叶节点及当前已验证嵌套视图），不能证明所有原始字图里不存在可挖掘的潜在小部件。

## 层级遗漏进一步拆分

复用现有 `expand_views`，增加被审计目标部件名称，仍保持原有完整笔数、有序参考对应、节点映射、精确上下文和参考形状阈值：

- 在上述 173,580 笔中，34,346 笔可在拆分后的子部件层找到合格候选。
- 若包含“仅有同字来源”类别，子部件候选潜在覆盖合计 37,617 笔。
- 此处没有对这些候选全量放置验收，不能计为实际新增覆盖。
- 另有 1,352 个仍含回退的作者—目标字，可从其他字的完整部件中找到满足源映射条件的整字候选，目标根结构也达阈值；当前没有对应的“部件到整字”通道。这与主表重叠，不能相加。

因此，补采清单不能直接由旧的“no compatible cross-character source component”消息推出。

## 有限诊断验证

选择常用字及全部 3 个“原池超过16候选仍回退”的槽位，进行了 89 个作者—目标—部件任务的诊断：

- 上下文桥接：76 个任务中 51 个找到满足原有有序对应与几何准入的完整来源。
- 完整部件到整字：10 个任务中 6 个通过。映射置信度不足的目标不放行。
- 候选尾部：3 个任务中仅 1 个通过；其完整来源位于原池第18位。
- 这些是有意选出的诊断字，并非随机留出，也不是全库收益估计。同字多个任务独立运行，不直接累加覆盖。

诊断桥接只改变候选可达范围；身份、变体、笔数、全局有序映射与原有有序参考对应阈值继续保留。整部件使用相同正等比变换。候选池外部件被显式加入诊断上下文后，仍调用原来的 `verify_complete_source`、`attempt`、`emit` 和逐点来源完整性检查，未修改这些函数。

另对一个大部件未展开的目标做了独立试摆，使用已有验证展开器后，原先0笔作者来源变成9/13笔；另一项上下文桥接实验单独恢复其4笔心部。未将两项实验相加宣称已得到13/13。

反例保留：存在可靠完整目部，但当前摆放造成新的跨部件交叉；逐笔映射均值0.5411低于0.55的来源；逐笔分数尚可但组件结构置信不足的整字来源；完整来源存在但目标根置信度0.7的字。这些都不能仅凭“有原轨迹”放行。低分表示证据不足，不等于已经确认写错或映射错。

## 后续顺序

1. 有限、可追溯的上下文桥接与目标嵌套展开，优先验证已经有真实来源的槽位；保留内容身份及碰撞约束。
2. 完整部件到整字的通道单独验证，避免强制把已有完整实例再拆小后回退。
3. 候选尾部搜索可小范围加入，但本次直接涉及的回退槽位仅3个，不能当主要解法。
4. 对真实新增跨部件碰撞研究布局或更合适来源；不把作者内部自然交叉重新定为缺陷。
5. 修复有证据的结构映射缺陷，再对仍缺可靠来源的部件补采。
